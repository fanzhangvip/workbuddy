## 0. 一句话结论

**这本书不能等写完再去 AI 味，骨架本身就得是去 AI 味的装置。**

下面这套规范融合了三样东西：本地技能 `training-deai`（治结构/句式）、新装的 `humanizer-zh`（保真/防改写走样）、以及我们自己的 A 系列六段骨架。

## 一、两件工具，分工完全不同

| | `training-deai`（本地已有） | `humanizer-zh`（本次安装） |
|---|---|---|
| **治什么** | **写出来的 AI 味**：结构太整齐、句式单调、词太空、语气太正面、信息太虚 | **改坏了的风险**：改写时编数据、丢限定、把"可能"写成"确定"、把作者的立场改掉 |
| **分层** | L1 结构 / L2 句式 / L3 词汇 / L4 语气 / L5 信息 | A–F 共 31 个检查点（A 铺垫、B 节奏、C 拔高、D 排版、E 聊天残留、F 中文特有问题） |
| **强项** | **改写顺序**（L1→L5→L4→L2→L3，先换词必失败）+ 检测脚本 | **保真约束**（最高优先级）+ 作者声音匹配 + 文件保护 |
| **比喻** | 手术刀 | 验血报告 + 手术安全规程 |

**两者都要用，缺一不可。** 只用 training-deai，容易改嗨了把事实改掉；只用 humanizer-zh，改完还是能看出机翻味。

## 二、铁律：保真 > 去味（冲突时永远让位）

这是本书最重要的一条规矩，直接抄自 humanizer-zh 的约束优先级：

```
1. 保留信息和确定程度   ← 最高，不可让步
2. 遵守编辑范围和文体
3. 匹配作者声音
4. 处理具体表达问题     ← 最低
```

**落到我们这套书，意味着：**

- **绝不为了"读起来更自然"而编造**案例、数字、时间、人名、来源。书里的每一个真实课例都必须来自教研组的录制素材
- **绝不把限定改掉**："8 个学生基础较弱"不能改成"基础普遍薄弱"；"我在三个班试过，两个有效"不能改成"实践证明有效"
- **绝不把推测改成结论**：AI 说"可能与内存泄漏有关"，改完还是"可能"
- 缺数字的地方，写成 `【待补：实际数据】`，**交回教研组补，不许自己填**

## 三、三处冲突，必须划清边界（否则写手会误删）

这两套规则有真冲突。不预先划清，写手会照着一条把另一条要的东西删掉。

### 冲突 1：章末的"交棒"要不要删？

- `humanizer-zh` §4 说：删除"接下来让我们深入看看"这类**只预告下文的句子**
- `training-deai` 手法10 说：**删总结句**，但"每章末尾可以有一句承接下一章的话"
- 我们的六段骨架要求：**每章结尾必须有下章预告**（这是三层联系里的"章间交棒"）

**边界判定——看它有没有承载信息：**

| 写法 | 判定 | 处理 |
|---|---|---|
| "接下来，让我们进入下一章的学习。" | 空预告，无信息 | **删** |
| "下一章我们讲出题和判分，难点在控制难度、主观题量大。" | 有实质信息（点名了下章的难点） | **保留** |

**写成规则**：章末预告必须包含"下一章解决什么具体问题"，否则就是废话，删掉。

### 冲突 2："补数字"和"不许编造"哪个听谁的？

- `training-deai` 手法7 说：补具体数字
- `humanizer-zh` 说：**不增加原文未提供的事实、数字**

**两者其实一致，只是说法不同**：`training-deai` 自己就写了"如果没有真实数字，写成 `【待补：实际数据】`，不要编"。

**写成规则**：补数字的对象是**教研组提供的素材**，不是凭空生成。稿子里出现的每个数字都必须能追溯到素材包。

### 冲突 3："口语化"要到什么程度？

- `training-deai` 说：不能过度口语化，"内部资深同事写的文档"，不是"朋友圈文案"
- `humanizer-zh` 说：随笔保留个性，**商务和学术文本保留必要正式度，不强行口语化**

**写成规则**（两系列分开定）：

| 系列 | 语域目标 | 允许 | 禁止 |
|---|---|---|---|
| **A 系列** | 一位有十几年教龄的老师跟你聊天 | 第一人称、口语短句、承认踩坑、偶尔括号补充 | 网络流行语、感叹号连用、"宝子们" |
| **C 系列** | 一位行业观察者在给你讲行业 | 短段落、冒头结论、直接称呼"你" | 教程式步骤、操作截图描述 |

## 四、融合后的改写流程（六步）

**每一章定稿前必须走完这六步，顺序不能变。**

| 步 | 动作 | 用哪套规则 | 产出 |
|---|---|---|---|
| **1** | **L1 结构**：重排段落、拆散"三点式"、删总结句 | training-deai | 结构稿 |
| **2** | **L5 信息**：补细节、补案例、补限制条件；缺数据处标 `【待补】` | training-deai 手法 5/7 | 内容稿 |
| **3** | **L4 语气**：降低确定性、至少留一处"这点我们还没验证" | training-deai 手法 5 | 语气稿 |
| **4** | **L2 句式**：长短句混排、删形容词收尾、删万能过渡句 | training-deai 手法 6/8 | 句式稿 |
| **5** | **L3 词汇**：最后才做同义替换（此时结构已定，不会破坏节奏） | training-deai 标记词表 | 语言稿 |
| **6** | **保真核对**：对照原文核 A–F 检查点，确认没编没丢没强化 | **humanizer-zh 全套** | 定稿 |

> **为什么 L3 放最后？** 先换词是最常见的失败做法——换完发现结构还是 AI 味，白做。这是 `training-deai` 里最值钱的一条经验。

**第 6 步的核对清单（humanizer-zh，逐条过）：**
- [ ] 每个新增的具体信息，都能在原文或素材包里找到吗？找不到就撤回
- [ ] 独立信息、否定、限定、时间、范围、归因，是否完整？
- [ ] 有没有把"可能"写成"确定"、"计划"写成"已经"？
- [ ] 调整排比/句式后，有没有丢内容或添出新项目？
- [ ] 表格数据、列表项、标题层级、代码块、链接是否保持原样？

## 六、战略结论：六段骨架本身就是去 AI 味的装置

这是我们这套书最值钱的一个设计判断。

**A 系列单章六段骨架：**
```
钩子 → 本章论点 → 为什么 → 怎么做 → 案例(含踩坑) → 小结+衔接
```

**对照 AI 味的五层问题，它天然带着抗体：**

| AI 味问题 | 六段骨架怎么自动解掉 |
|---|---|
| L1 结构太整齐 | 六段的长度天然不均（"怎么做"占 50–60%，"钩子"只占 6%） |
| L4 语气 100% 正面 | **"案例"段强制要求写踩坑**——AI 自己不会写失败案例 |
| L5 信息空洞 | **"钩子"段强制要求具体场景**；"案例"段强制要求具体人物和数字 |
| L2 句式单调 | 钩子是叙事短句，为什么是长句讲机制，天然混排 |
| L3 词汇 | 第一人称叙述 + 大白话设定，天然排斥"赋能/抓手" |

**所以我们的产能逻辑是**：不是写完再去味，而是**用一个自带抗体的骨架去写**，去味的工作量压到最低。

### 实测数据（第 3 章）

**⚠️ 跑检测必须只喂正文。** 把说明书、附录一起喂进去，分数会失真——我们第一次就踩了这个坑（当时误报"整份 0 分"，其实是附录的散文把变异系数拉高了）。

| 口径 | 字数 | AI 味指数 | 句长变异系数 | 段落变异系数 |
|---|---|---|---|---|
| 整份文件（说明+正文+附一+附二） | 6842 | 0 / 100 | 0.596 | 0.437 |
| **只跑正文——原稿** | 4943 | **8 / 100** | 0.496 | 0.405 |
| **只跑正文——定稿** | 5066 | **0 / 100** | 0.505 | 0.428 |

**关键结论**：正文口径下，原稿 8 分（唯一扣分项是"句长偏单调"），按六步流程精修后降到 0 分。**变异系数 0.5 上下是健康区间**——AI 写作通常低于 0.3（句长太齐）。定稿示范见《A01_第3章定稿_去AI味全流程示范.md》。

> **提醒**：脚本不查 L4/L5，0 分不代表可以放心交付，人工代入审读仍然必做。

## 七、几个"看着像 AI 味，其实要保留"的边界案例

写手最容易在这里删错东西。以下三处在样章里都出现过，**判定为保留**：

| 写法 | 会不会被误判 | 为什么保留 |
|---|---|---|
| "本章口诀：想清楚，再提问；AI出初稿，我来定乾坤。" | 对仗工整，像"四字词排比"（humanizer-zh §29） | 它是**有意设计的记忆锚点**，属于"作者有意使用"的边界；口诀的功能就是好记，不该为了"不整齐"而破坏 |
| "本章小结：一口气记住三句话" | 三句式，像"强凑三段式"（§6） | 这三句分别对应本章三个不同动作，**各自提供独立信息**；§6 明确说"只有重复或空泛时才合并" |
| 四个"我踩过的坑" | 看起来像编号列表 | 是**真实失败经验**，是 L4 抗体的核心，删了反而更像 AI |

**判定的通用问法**：删掉这段，读者会少知道一件事吗？会 → 保留。

## 八、给写手的操作指引

**动笔前**：把六段骨架的每一段目标字数贴在面前（钩子 6% / 论点 5% / 为什么 12% / 怎么做 55% / 案例 17% / 小结衔接 5%）。

**写的时候**：按骨架顺序写，不要回头改。第一稿允许有 AI 味。

**写完一章**：走第四节的六步流程，跑检测脚本，做代入审读。

**交付时**：附一份 `【待补清单】`，列出所有 `【待补：实际数据】` 的位置，交回教研组补真实素材。**宁可留白，不许编造。**

**调用技能时**：
```
用 training-deai 处理第X章，然后跑 humanizer-zh 做保真核对
```
或者直接说"这一章去下 AI 味"，两个技能会先后介入。
