### 行业AI提效真实场景运用
- 零售 / 电商
  - 痛点：运营每周人工写5份竞品分析，耗时2天
  - AI解法：WorkBuddy自动抓取+分析，10分钟生成报告
- 金融 / 银行
  - 痛点：合同审查人工需2小时，容易遗漏风险点
  - AI解法：上传PDF，3分钟提取关键条款和风险项
- 医疗 / 健康
  - 痛点：患者反馈每月几千条，人工分类整理要一周
  - AI解法：批量导入数据，自动分类+生成问题优先级报告
- 制造 / 工厂
  - 痛点：设备日志靠人眼找异常，效率低且容易漏
  - AI解法：导入日志，自动识别异常模式，生成质检周报
- 教育 / 培训
  - 痛点：作业批改耗时耗力，学情报告全靠老师手写，难以规模化
  - AI解法：WorkBuddy批量批改作业+自动评分，5分钟生成全班学情报告
- 政务 / 公共服务
  - 痛点：表单汇总+汇报材料撰写最耗时
  - AI解法：多份表格合并，自动提炼数字+生成汇报PPT
- 物流 / 供应链
  - 痛点：运单数据分析靠Excel手动透视，输出慢
  - AI解法：导入运单数据，自动识别异常环节+输出优化建议
- 能源 / 公用事业
  - 痛点：多源能耗数据整合分析需要专业团队
  - AI解法：多表格整合，自动生成能耗趋势分析+降本建议

### Harness Engineering：Agent 运行时外壳
- Harness 是什么：让模型变成可执行系统的工程外壳
- Prompt Engineering、Context Engineering、Harness Engineering 的区别
- Harness 六层架构
  - 信息边界层
    - 信息契约：定义Agent接收、处理和输出的信息结构
    - 上下文边界：控制哪些信息进入模型上下文
    - 信任边界：区分系统指令、用户输入、企业知识和外部内容
  - 工具系统层
    - 能力注册：统一描述Agent可以使用的工具
    - 工具接入：连接MCP搜索、知识库、缓存和文件等外部服务
    - 权限边界：控制不同Agent可以调用的工具范围
  - 执行编排层
    - 任务建模：将复杂任务拆分为节点、阶段和Agent
    - Agent协作：定义不同Agent的职责和数据传递关系
    - 控制方式：支持顺序、分支、并行、循环和人工参与
  - 记忆与状态层
    - 运行状态：记录Agent当前任务进度和中间结果
    - 状态持久化：支持任务暂停、继续和故障恢复
    - 长期记忆：保存可跨任务复用的用户信息和业务知识
  - 评估与观测层
    - 运行观测：记录日志、Trace、节点耗时、工具调用和异常信息
    - 质量反馈：向系统提供结果质量和执行质量信号
    - 问题定位：支持分析失败发生在哪个Agent或执行阶段
  - 约束、校验与恢复层
    - 执行约束：定义Agent运行时必须遵守的边界
    - 结果校验：检查输入、工具结果和模型输出是否符合契约
    - 恢复机制：定义异常发生后的停止、重试、降级和恢复方式

  - 工程参数：温度 0.1、max_tokens 200、单次调用、6 秒超时
  - Prompt 即代码：12 条意图定义 + 3 条 few-shot + 「只分类不回答」，放入 prompts.py 并纳入回归测试
  - 路由失败结构性降级：落 intent.route status=degraded，退回关键词路径，不抛异常给用户
- 模块四：事实底座：账本、状态机与冲突治理
  - append-only 账本：SQLAlchemy 只插入，投影用纯函数完成，绝不原地 update
  - 事实状态机：provisional → confirmed → revoked，conflict → reconciled，携带 revision / source_type / confidence / evidence
  - FactConflictEdge 互斥图：一次算出 selected / reconcile / revoke / release 四组结果
- 模块六：长期记忆：双源分工与检索-遗忘闭环
  - 双源分工（ADR-0006）：本地 interaction_ledger 是唯一事实源；Memobase 只存可变综合记忆，永不接收比赛事实
  - 记忆单位 Moment：user_fact / emotional_exchange / promise / match_event 四类，importance 本地定不被远端覆写
  - 写入可靠性：asyncio.Queue 容量 256，失败移交持久积压表，最多 10 次退避重试，绝不静默丢弃
  - asyncio 下的坑：消费任务常驻可取消、lifespan 启动、优雅关闭排水、记得 await queue.join()
  - 召回：recall + 时间衰减 + source 出处；上界 10 条 / 12 条画像 / 480 字符
  - 向量路：httpx 调本地 bge-m3（2 秒超时、截断 2000 字符）+ pgvector vector(1024)，留空即停用自动退回关键词
- 模块七：关系导演与人格：什么时候闭嘴
  - PersonaDirector：把关系等级、偏好、比赛上下文、最近信号折叠成可执行的 Decision（Pydantic）
  - 人格三轴：initiative_mode（主动性）/ analysis_appetite（分析胃口）/ banter_level（吐槽尺度）
  - tier 派生量 vs 粘性设置：只镜像 appetite，单测断言 initiative 必须为空——用测试守护架构意图
  - cue 枚举：CueAcceptedJudgment / CueAcceptedInitiative / CueBanterAllowed，把「用户接受我了」翻译成可计算事件
  - 实战产出：同一比赛跑出「安静型 / 懂球型 / 毒舌型」三种人格的回复对照表
- 模块八：表达层：Decision → Realize → Presentation
  - ForbiddenClaims 关键设计：把「不许说什么」从 Prompt 自然语言下沉为下游必须遵守的数据结构字段
  - Presentation 白名单：client_allowed_motions 限定 12 动作组 / 17 动作，用 Literal 直接锁死——约束词表比约束描述有效
  - 感知延迟优化：先发字幕后发语音；反重复哈希防复读机上身
- 模块九：护栏系统：把「不许说」写成代码
  - guard_validate_reply 四重检查：句数字数、ForbiddenClaims、锚定纪律（提及事实必须在账本里）、反重复
  - 拒绝必须留痕：reject_reason 记录 policy / empty 分类，「为什么这次没说话」可查可归因
  - 事实类回复路径完全绕过 Realize：确定性模板 + 账本数据，句级事实错误从根上不会发生
  - 实现建议：写成纯函数 + 返回 GuardResult(passed, reason)，方便 pytest 表驱动覆盖
- 模块十：可靠性工程：熔断、超时与降级
  - 三态熔断器 CLOSED / OPEN / HALF：3 次失败开路 10 秒，half-open 单探针放行
  - 传输层零重试的具体做法：显式关闭 httpx 重试，语义层重试交给 tenacity 按异常类型分别退避
  - 分级超时：路由 6 秒 / 结构化 10 秒 / Embedding 2 秒，用 httpx.Timeout(connect, read) 分别设置
  - 异常分类设计：TransientError / PermanentError 基类，LLM、网络、认证、限流各自继承，让 tenacity 按类型决定策略
  - 结构性降级全景：路由退关键词、Realizer 有确定性底稿、TTS 降文本、记忆入积压、知识库不碍主流程
- 模块十一：评测体系：让「感觉不好」可定位
  - 规模与结构：12 个用例域——boundary 38、baseline 36、regression 26、memory 24、safety 22、robust 19 等
  - 五个确定性 grader：truth、claim_safety、trajectory、trace、voice；Scorecard 输出 pass_rate / fact_safety_rate / trace_complete_rate
  - 确定性夹具：patch 替换 Realizer / Router，respx 或 httpx.MockTransport 拦截 HTTP，AsyncMock 覆盖异步路径
  - 回归收容五步法：先冻结不可变 regression 用例复现，再改产品，永不静默 rebaseline
  - 标志性观点：LLM judge 不是事实权威——主观评分必须先与人类标注校准，否则不得影响发布决策
- 模块十二：工程质量防线：契约、测试与交付
  - 测试六层金字塔：纯函数单测 / Mock 单测（AsyncMock、respx）/ 集成测试（直调节点）/ 异常专项 / 异步测试 / 浏览器 E2E
  - 跨端契约闸门五个：presentation-map、event-model 逐字节对拍、transport 幂等语义、draft-form、idle-yield——与后端语言无关，不用重写
  - Alembic 迁移 lint：检查 revision 链唯一与线性，避免多人协作分叉
- 模块十三：安全、隐私与幂等：可信链最后一块
  - 信任边界三分类：用户端短期会话令牌 / 导播台运营令牌 + scope / 外部数据源
  - 身份不可伪造：user_id 只从令牌 sub 取，消息体携带不一致即 403——值得背下来的一条规则
  - 密码与留痕：passlib PBKDF2 十万次迭代，刷新令牌只存哈希；保留期音频不落库、文本 30 天、运营审计 180 天
  - 幂等写入：Idempotency-Key 四态响应，事件 + 幂等记录 + Outbox 在同一 session 事务内，最多重试 10 次
- 模块十四：面试包装、高阶问答与展望
  - 一句话讲法：「数据源延迟大于用户感知时，还能保证它说的话既准确、又不得罪人」；三句话讲法：问题 → 解法 → 结果
  - 高阶问答要点：并发（串行化 + 观察上限 5）、延迟（分层预算 + 字幕先行 + to_thread）、一致性（revision 比对 + 重跑）、成本、灰度
  - 面试加分「诚实句」：限流没做会用 Redis 令牌桶补；LLM judge 不判事实；至少一次投递 + 客户端去重，生产还需 ACK 与重放游标
