## 一、国外主流：欧美商业书的结构范式

欧美商业书（Business Book）的结构是高度工业化的——因为读者是"忙碌的专业人士，要的是清晰，不是文学上的模糊"。这套结构被反复验证，可以直接借用。

### 1.1 全书三段式骨架构

| 部分 | 占比 | 内容 | 读者读完后应该想什么 |
|---|---|---|---|
| **Part 1 基础/问题** | 15–20% | 诊断问题、说明为什么老办法不管用、建立紧迫感 | "这个人完全懂我的处境，而且我一直用的办法是错的" |
| **Part 2 框架/方法** | 60–70% | 核心方法，**一章一个支柱/步骤** | "我知道该怎么做，而且有具体步骤" |
| **Part 3 应用/落地** | 10–15% | 全流程演练、障碍与边界、扩展、下一步 | "我今天就能开始" |

### 1.2 单章七要素（这是最有价值的部分）

欧美商业书的每一章，几乎都是这个模板：

```
1. Chapter Thesis  章节论点 —— 一句话说清"读完这章读者理解了什么"
2. Opening Hook    开头钩子 —— 一个故事、一个惊人数据、一个bold claim
3. Key Points      3–5 个要点，每个都要有证据支撑
4. Framework       本章的模型/流程/工具（可图示化）
5. Case Study      案例：Before → Attempt → Breakthrough → After（量化结果）
6. Pitfall         常见错误：这个阶段最容易翻车的地方
7. Exercise/Bridge 给读者的练习题/模板 + 与下一章的衔接
```

### 1.3 一句话铁律：**一章一个问题**

> "Each chapter should answer one clear question. If a chapter answers two questions, **split it**. If it answers half a question, **merge it** with another."
> （每章回答一个明确的问题。答了两个就拆开，答了半个就合并。）

这条铁律是判断目录好坏最省事的标准。

### 1.4 转型弧（Transformation Arc）

好的商业书都在描述**读者的一次转变**：

```
起点状态：困惑 / 卡住 / 不确定 / 一直在做错
    ↓
终点状态：装备好了 / 自信 / 清楚下一步该干什么
```

**这条弧线不是写出来的，是在动笔前设计出来的。** 它不会从"写我感兴趣的章节"里自然生长出来。

配套的五段式：
```
Hook（点名读者的问题）→ Reframe（给出颠覆性视角）→ Evidence（证明）→ Method（方法）→ Transformation（愿景）
```

### 1.5 格拉德威尔式单章悬念结构（叙事型章节）

马尔科姆·格拉德威尔（《眨眼》《异类》）普及的一套单章写法，被大量非虚构书沿用：

```
① 用一个小众但可信的故事开场（真实人物/公司/小镇）
② 在章节 50% 处留下悬念，故事中断
③ 插入作者解读，点出对读者的启示
④ 解决悬念，把故事讲完
⑤ 以要点总结收尾
```

**这套结构特别适合"讲故事 + 讲道理"交替的章节**，能同时做到"教育和娱乐的平衡"。

## 二、日本商业书（ビジネス書）的做法

日本商业书长期占据东亚实操类图书的主流，它的特点是**极端的好读性**：

| 做法 | 说明 |
|---|---|
| **冒头结论** | 每章开头先给结论，再讲理由（不是"铺垫三页才说正事"） |
| **1 テーマ 1 見開き** | 一个主题占一个跨页（左右两页），读者翻到哪都能独立读懂 |
| **图解优先** | 能用一张图说清的，不用 500 字；概念必配示意图 |
| **具体化** | 拒绝"要有全局观"这类空话，一定落到"第一步做什么" |
| **口语化** | 用"你"直接对读者说话，不用"笔者""本文" |

**我们的 C 系列（品牌轻书）应该大量借用这套做法**：极短段落、每节一个论点、图解优先。

## 三、教程/工具书的做法（与我们的书最接近）

### 3.1 核心闭环：认知—理解—练习—反馈

> 优秀的教程书不是简单罗列功能菜单，而是构建一个"**认知—理解—练习—反馈**"的完整学习闭环。

### 3.2 四段式单元（每个功能点/小节都按这个写）

```
① 场景描述 —— 先给一个真实场景（某人遇到了某个具体问题）
② 操作步骤 —— 逐步演示，配高清截图 + 标注
③ 注意事项 —— 容易忽略的地方
④ 错误示例 —— 做错了会怎样（正反对比）
```

### 3.3 章节结构（教程类通用）

```
知识点讲解 + 操作步骤截图 + 实战案例 + 小测验/练习题 + 常见误区提示
```

### 3.4 视觉化的硬要求

- **每个操作步骤配图**：用箭头、高亮色块标出关键操作区域，避免模糊描述
- **复杂流程配流程图/思维导图**，比文字清晰
- **颜色编码**：绿色=成功操作，红色=警告或错误，蓝色=提示
- **二维码短视频**：满足不同学习风格（纸质书的重要延伸）

### 3.5 一个简单好用的验收标准："5 秒测试"

> 让目标读者只读标题和首句，能否在 5 秒内理解这节要讲什么？
> 如果一个步骤被多位试读者反馈"难以理解"，就必须补充说明或简化操作。

## 四、中文畅销工具书：这个赛道的做法与陷阱

### 4.1 主流做法：场景化拼盘

看看市面上销量最高的那批（《一本书玩转DeepSeek》《DeepSeek实战技巧精粹》等），结构高度一致：

```
第一部分：AI 革命的本质（讲趋势）
第二部分：核心功能与提示词技巧（讲能力）
第三部分：N 大场景应用（讲用法）
```

宣传语也一致："13 大场景 / 90 个案例 / 100 个提示词模板"。

### 4.2 陷阱：**场景拼盘的"零散化"**

这套结构的致命问题是：
- **无主线**：读完记住的是一堆碎片，不是一套方法
- **无递进**：第 5 个场景和第 15 个场景没有关系，可以随便换顺序
- **无获得感**：读者"知道AI能干这个"，但"自己什么都没做出来"
- **同质化**：十几本书都是这个结构，读者分不清谁是谁

**这正是我们的机会**——用"一条主线贯穿到底"替代"场景拼盘"。

## 五、我们的结论：A 系列用什么结构

**一句话：用教程书的骨架 + 商业书的叙事。**

- 骨架（能不能学会）→ 借教程书的"认知—理解—练习—反馈"闭环 + 四段式单元
- 叙事（愿不愿意读）→ 借商业书的"章节论点 + 开头钩子 + 案例 + 衔接"

### 5.1 A 系列单章骨架（六段，全书统一）

```
① 钩子        一个真实现场（"上周三晚上9点，我还在写明天的教案"）
② 本章论点    一句话说清这章要解决什么、读完你能得到什么
③ 为什么      讲清这件事的底层逻辑（不长，1–2页）
④ 怎么做      分步实操 + 截图 + 模板（本章主体，占 50–60%）
⑤ 案例        一个完整真实案例走一遍（含"我踩过的坑"）
⑥ 小结 + 衔接 本章口诀 + 一句话预告下一章
```

### 5.2 三个层次的"内在联系逻辑"

这是用户最关心的部分——书不能是章节的堆砌。我们用三层锁死：

**第一层：章内联系（本章六段是一条因果链）**
```
钩子制造问题感 → 论点给出承诺 → 为什么建立认知 → 怎么做给出路径 → 案例证明可行 → 小结固化
```

**第二层：章间联系（每章结尾必须"交棒"）**
- 每章结尾一句话预告下一章，且**下一章必须是本章的自然延伸**
- 例：第3章"把课备完"结尾 → "课备好了，接下来要出题和判分，这是下一个大坑" → 第4章
- 判断标准：**把任意两章的顺序对调，读起来是否别扭？** 如果不别扭，说明章间联系不够。

**第三层：全书联系（一条主线从头贯穿）**
- A01 的主线：**一位老师的"一学期工作流改造"**
- 每章 = 学期里的一个真实节点：开学 → 备课 → 出题 → 批改 → 期中分析 → 家长会 → 期末教研
- 读者读完全书，手上是一套**完整跑通的助教工作流**——而不是 12 个孤立的技巧

### 5.3 每章的硬性要求（写作时对照自查）

| 要求 | 标准 |
|---|---|
| 一个问题 | 本章只回答一个明确问题，多一个就拆 |
| 一句话论点 | 能用一句话写出本章论点，写不出就是没想清 |
| 一个钩子 | 开头 300 字内必须出现具体场景 |
| 一个交付物 | 本章结束，读者必须"得到"一样东西（模板/文件/成品） |
| 一个案例 | 至少一个完整真实案例，含"踩过的坑" |
| 一句衔接 | 结尾必须有下章预告 |
| 5 秒测试 | 每个小节标题 + 首句，5 秒能读懂 |
| 配图 | 每个操作步骤配截图，复杂流程配流程图 |

### 5.4 章节字数与节奏

- 单章 5000–7000 字（附录除外）
- 段落短：**一段不超过 5 行**，一屏能看完
- 每 800–1000 字必须出现一个"锚点"：一张图、一个模板、一个案例、一句加粗结论
- 杜绝：连续 3 页纯文字无图无案例
