# 企微聊天记录归档系统 · 说明

一个「后端 + 前端」的完整系统：扫码登录一次 → 定时把全部员工的聊天记录拉到 PostgreSQL → 在网页上像微伴后台一样浏览会话与消息。

---

## 一、整体架构

```
┌──────────────┐   ①签名   ┌─────────────────────┐
│  微伴 OpenAPI │ ←──────── │                     │
│  (元数据)     │           │   FastAPI 后端       │
└──────────────┘           │  127.0.0.1:8848      │
        │                  │                     │
        │ 会话/消息元数据     │  · auth_service     │
        ▼                  │  · sync_service     │
┌──────────────┐   ②开会话  │  · scheduler        │
│  企业微信      │ ←──────── │                     │
│  getchatdata │           └──────────┬──────────┘
│  (明文正文)   │ ──③明文──▶           │
└──────────────┘                      ▼
                            ┌─────────────────────┐
                            │  PostgreSQL :5433    │
                            │  weiban_chat         │
                            └──────────┬──────────┘
                                       │ REST /api/*
                                       ▼
                            ┌─────────────────────┐
                            │  Vue3 前端 (:5173 /  │
                            │  由后端 8848 托管)    │
                            │  总览/会话管理/同步/登录│
                            └─────────────────────┘
```

**核心结论（已实测验证）**：微伴 OpenAPI 不返回消息正文，但它给了「锁 + 钥匙」——
`original_id` 是企微 `msgid`，`secret_key` 是解密密钥。把这俩提交给企微
`/chatdata/getchatdata`，**由企微云侧解密**回传明文。因此：

- 不需要企业 RSA 私钥
- 不需要会话存档 SDK
- 不需要逐会话打开网页

唯一需要浏览器的环节是**扫码登录拿凭据**。好消息：微伴登录态是滑动过期的，
开启保活后**基本不再需要重新扫码**（见「八、凭据保活」）。

## 三、启动

### 1. 启动数据库（首次一次）

```bash
docker compose up -d
```

或手动：

```bash
docker run -d --name weiban-chat-pg \
  -e POSTGRES_PASSWORD=weiban123 -e POSTGRES_USER=postgres -e POSTGRES_DB=weiban_chat \
  -p 5433:5432 --restart unless-stopped pgvector/pgvector:pg16
```

连接串写在 `.env`：

```
DATABASE_URL=postgresql://postgres:weiban123@127.0.0.1:5433/weiban_chat
```

### 2. 启动后端

```bash
start_backend.bat
# 或
python -m uvicorn backend.main:app --host 127.0.0.1 --port 8848
```

启动时自动建表，并读取 `SYNC_INTERVAL_MINUTES` 决定是否开启定时同步。

### 3. 前端

**生产模式（推荐）**：先 `build_frontend.bat`，然后直接访问
**http://127.0.0.1:8848** —— 后端会托管 `frontend/dist`。

**开发模式**：`start_frontend.bat`，访问 http://127.0.0.1:5173（已配好 `/api` 代理）。

## 四、使用流程

1. **登录与凭据页** → 点「弹出浏览器扫码登录」→ 在弹窗里用企业微信扫码。
   脚本会自动抓取微伴与企微的 cookie 并缓存，之后**不再需要浏览器**。
   可点「校验凭据是否有效」验证通道。
2. **同步中心页** → 选员工范围 / 会话类型 / 上限 → 「开始同步」。
   进度实时刷新；可随时「停止」。开启定时后每 N 分钟自动增量同步。
3. **会话管理页** → 左侧选员工、搜索客户，右侧看消息气泡。
   支持会话内搜索、加载更早消息、图片/语音/文件展示。
4. **总览页** → 全局统计 + 按正文全文检索，点结果直接跳到对应会话。

## 五、数据表

| 表 | 说明 | 幂等键 |
|---|---|---|
| `staff` | 员工 | `staff_id` |
| `chat_session` | 会话 | `(staff_id, session_id)` |
| `chat_message` | 消息（含解密正文） | `(staff_id, session_id, message_id)` |
| `sync_cursor` | 每会话的同步水位 | `(staff_id, session_id)` |
| `sync_job` | 同步任务与进度 | `id` |
| `credential` | 登录凭据登记 | `id = 1` |

`chat_message.content_state` 取值：
`ok` 已解密 / `pending` 待解密 / `empty` 明文为空（如纯图片消息）/ `fail` 无密钥。

## 七、同步参数说明

| 参数 | 默认 | 说明 |
|---|---|---|
| `kind` | `incremental` | `full` = 忽略水位重新拉全部 |
| `staff_ids` | 空 = 全部 | 指定员工则只同步这些 |
| `session_types` | `["ext_user"]` | 客户 / `room` 群聊 / `other_staff` 同事 |
| `max_sessions_per_staff` | 200 | 按最近活跃排序取前 N 个，`0` = 不限 |
| `max_msgs_per_session` | 0 | 每会话最多拉多少条，`0` = 不限 |

**增量是怎么快的**：`sync_cursor` 记录每个会话已同步到的时间水位。会话的
`last_msg_time` 没超过水位就**直接跳过，一次请求都不发**。所以定时增量同步开销很小。

## 八、凭据保活（免扫码自动续期）

**背景**：微伴后台没有账号密码登录（只能企业微信扫码），曾以为凭据失效就必须人工重新扫码。实测发现并非如此：

> 微伴登录态是**滑动过期**的 —— 每访问一次后台，`session_id` 的过期时间就被重置为「当前时间 + 7 天」。
> 实测数据：访问前 exp=`10-20 21:00:59` → 访问后 exp=`10-20 21:17:58`。

因此只要定期访问一次后台，登录态就**永不过期**。系统在两个层面自动做这件事：

| 层面 | 机制 | 配置 |
|---|---|---|
| 定时兜底 | 后端每 6 小时自动保活一次 | `.env` `KEEPALIVE_INTERVAL_MINUTES`（0=关闭） |
| 同步前体检 | 每次同步任务开始先校验凭据，超过 48 小时未刷新就先保活 | 内置，无需配置 |

**安全设计**：保活脚本**先校验再写盘** —— 新 cookie 调不通 `jsapi_sign` 就拒绝写入，保留原凭据（自动备份到 `.cache/ww_bootstrap.bak.json`）。

**手动操作**：

```bash
python wb_keepalive.py --check    # 只校验
python wb_keepalive.py            # 立即保活一次
python wb_keepalive.py --status   # 查看 JSON 状态
```

前端「同步中心 → 凭据保活」卡片可查看状态、调整间隔、手动触发。

> 注：保活需要常驻 Chrome（CDP 端口 9222）。若浏览器被关闭，脚本会自动用
> 已登录的 profile 重新拉起（`C:\Users\EDY\.workbuddy\browser-profiles\wb-session`）。

## 九、常见问题

**Q：报 `40058` / 解密失败？**
先跑 `python wb_keepalive.py` 保活；若提示需要人工登录，再到「登录与凭据」页重新扫码（开启保活后这种情况很少见）。

**Q：群聊（room）拉不到正文？**
企业微信侧一般不对群聊做会话存档，属于平台限制，不是系统问题。

**Q：某个会话一条消息都没有？**
该会话的 `agree_msgaudit` 为 `false`（对方未同意存档），同步时会自动跳过。

**Q：全量同步要多久？**
一个员工上千个会话时，全量约 1 小时量级。建议用增量 + 每员工会话上限，
或者挂夜间跑。首次建库时可只同步重点员工。

**Q：`content_state = empty` 是什么意思？**
该消息本来就是图片/表情/文件等无文字内容，不是解密失败。

**Q：凭据文件在哪？能提交 git 吗？**
`.cache/ww_bootstrap.json`，里面有 cookie（等同登录态），**不要提交**。
