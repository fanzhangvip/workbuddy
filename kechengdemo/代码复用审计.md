## 1. F1 · 聊天气泡渲染（**最严重，已造成 bug**）

### 证据

`frontend/src/` 下**没有 `components/` 目录** —— 零个公共组件。气泡是各页各写的：

| 页面 | 实现 | 自有样式条数 |
|---|---|---:|
| `ChatView.vue` | `.row.send/recv` + `.bubble-col` + `.msg-img` + 日期分隔 | 15 |
| `EvalView.vue` | `.bubble` + `.quote` + `.bd` + `.b-img` + `.b-file` | 13 |
| `ReviewView.vue` | 同上 | 14 |
| `ScoreView.vue` | `.ev` + `.ev-tag`（证据行气泡） | 2 |

**逐行比对 EvalView 与 ReviewView：11 条气泡样式全部逐字相同。**

### 已造成的代价（同一个根因，修了 5 遍）

1. 多行消息被拆成一串无角色气泡 → 全部靠左（case 26/30）
2. 左右方向判错（`indexOf(':')` 命中时间里的冒号；`startsWith('销售')` 永不命中）
3. 引用回复被误读为归属错误
4. 表情/图片不显示（媒体 URL 被剥）
5. 证据行显示原始 `#编号 [时间]` 噪音

### 方案

新增 `frontend/src/components/ChatBubbles.vue`：

```
props:
  messages  结构化消息数组（优先；带 media_url / is_media / role / msg_time）
  text      纯文本（兼容回退，内部走 parseConversation）
  compact   紧凑模式：给证据行 / 侧栏
  showDay   显示日期分隔：ChatView 需要
```

样式随组件走（`scoped`）。EvalView / ReviewView / ScoreView 直接替换删除本地样式；
**ChatView 暂不并**（它多出下载卡、`未解密` 标签、`content_state`），先记在文档里，
避免为统一而破坏一个本来就正常的页面。

## 3. B2 · 指数退避

### 证据

```python
# backend/outbox.py:26
def _delay(attempts): raw = min(BACKOFF_BASE * (2**max(0,attempts-1)), BACKOFF_CAP)
```

### 11.1 有意**没有**合并的（留痕，避免以后重复讨论）

相似度扫描还会报出一批 **4~5 行的短函数**，逐条核对后确认是**巧合**而非同一逻辑，
强行合并只会把不相干的东西绑在一起：

```
contracts.ContractViolationError.__init__  <-> http_client.HttpFailure.__init__
wb_bootstrap._kill_pid_tree                <-> wb_keepalive.cdp_alive
db.all_settings                            <-> grade_tag.ledger_state
db._setting_cast                           <-> scheduler._cfg_int      （一个走 app_setting，一个只读 .env）
scheduler._job                             <-> scheduler._scoring_job  （2 行守卫 + 启动作业）
api_review.list_reviews                    <-> api_scoring.assessments（过滤列完全不同；分页已共用）
weiban.list_external_users                 <-> weiban.list_sessions    （参数名不同；token 注入已共用）
```

### 11.2 这一轮顺带调整的**行为**（三处，都要知道）

1. **清理类定时任务补上 `max_instances=1, coalesce=True`**：原先只有同步/评分/保活带，
   reap、保留期、失败重投、标签排空没带 —— 某次跑得比间隔久就会**叠起来**对同一个库
   重复清理。现在统一由 `_reschedule_interval()` 一处保证。
2. **读接口的重试预算统一为「总 3 次尝试」**（`weiban.READ_ATTEMPTS = 3`）。
   改造前是 3 次 / 9 次混着（`list_staff` 3 次，其余 6 个读接口走
   「3 轮 × 每轮 3 次」= 9 次）——**没人选过**这个差异。同时把
   `request_retry` 的参数从「轮数 × 每轮次数」改成直白的**总尝试次数**，
   不再需要做乘法。写操作仍是**单次投递**（重试归 outbox）。
3. **10 个测试文件的通过行从 `  ok  ` 变成 `  PASS  `**（统一到 harness 的打印格式）。
   判定只看**退出码**，`run_all.py` 也只提取摘要行显示，不影响结果。

### 11.3 测试样板转换怎么做的（为什么敢一次动 31 个文件）

按形状分流，**能不动正文就不动**：

* **形状 A（19 个文件）**用 `PASSED, FAILED = [], []` 计数 →
  `from _harness import PASSED, FAILED, ROOT, check`：`import` 拿到的是 harness 里
  **同一对列表对象**，于是这些文件的结尾汇总代码**一个字都不用改**；
* **形状 B（10 个文件）**用 `_TOTAL/_FAILED` 整数计数（无法跨模块共享）→
  结尾两行换成 `return summary()`；
* 三个文件（`test_ctx_integration.py` / `test_ctx_preprocess.py` / `test_dedup_semantics.py`）
  自带断言风格，逐个手工处理。

脚本 `.workbuddy/tmp/b_harness_convert.py` 先 dry-run 打印每个文件要做哪几步，
确认 0 个「没匹配到」之后才 `--apply`（先备份）。
