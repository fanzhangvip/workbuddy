# 员工聊天记录导出 —— 使用说明

> 2026-10-13 打通。整套链路已可**纯 HTTP** 运行（不需要浏览器、不需要企业私钥、不需要官方 SDK）。

---

## 一、为什么能拿到明文（原理）

| 数据 | 从哪来 |
|---|---|
| 员工 / 会话 / 消息**元数据** | 微伴 OpenAPI（`session/list`、`message/list/v2`） |
| 消息**明文正文** | 企业微信 `chatdata/getchatdata` |

关键事实（实测确认）：

1. 微伴 OpenAPI 的 `content` / `text_content` **恒为 `null`**，但每条消息都带
   - `original_id` = 企微的 `msgid`（实测 27/27 完全一致）
   - `secret_key` = 该消息的解密密钥（实测与企微组件上送的完全一致）
2. 微伴网页后台能显示明文，是因为它内嵌了**企业微信官方「会话存档展示组件」**；
   页面把 `[{msgid, encrypt_info:{secret_key}}]` POST 给企微 `getchatdata`，
   **由企微云侧完成解密**并回传明文。
3. 所以：微伴给的是「锁 + 钥匙」，开锁的是企微。

**结论：我们不需要企业 RSA 私钥、不需要会话存档 SDK，也不需要逐个打开网页。**

## 二、三步流程

```
① 微伴 API   GET  /api/staff_client/jsapi_sign?url=...      → 签名
② 企微 API   POST /wwopen/monoApi/openData/frame/createOpenChatSession → sid
③ 企微 API   POST /chatdata/getchatdata?reqid=...
             body = {"items":[{msgid, encrypt_info:{secret_key}}], "sid", "reqid"}
             header Open-Msg-User-Sid: sid                    → 明文
```

实测要点（踩过的坑，改代码前先看）：

- `reqid` = `base36(毫秒时间戳) + "." + 随机串`，纯前端随机数、**无签名**，可自行生成
- `reqid` 必须**同时**出现在 query 和 body，否则报 `40058 reqid missing`
- body 里也必须带 `sid`（只放 header 同样 40058）
- **一个 sid 可复用、可跨会话** —— 解密任意会话都用同一个 sid
- 单次可提交上百条 items（本工具按 100 分片）

## 三、文件与职责

| 文件 | 作用 |
|---|---|
| `wb_bootstrap.py` | **凭据引导**（唯一需要浏览器的步骤）。抓微伴登录 cookie + 企微 `wwopen.open.sid`，存 `.cache/ww_bootstrap.json` |
| `ww_chatdata.py` | **企微正文解密客户端**（纯 HTTP）。负责签名、开会话、批量解密明文 |
| `wb_staff_export.py` | **主工具**。指定员工 → 会话 → 消息 + 正文 → Markdown / JSONL |
| `weiban.py` | 原有微伴 OpenAPI 客户端（元数据来源，未改动） |
| `wb_chat_export.py` | 早期「纯浏览器」版本，**兜底用**（签名接口若变动仍可用，但每会话约 10~20 秒） |

## 四、怎么用

### 1. 引导凭据（偶尔一次）

```bash
python wb_bootstrap.py
```

- 会自动挑一个员工 + 会话打开微伴消息页，抓取凭据
- 首次运行若未登录，会在弹出的 Chrome 窗口停住，**扫码登录后**会自动继续
- 输出：`.cache/ww_bootstrap.json`

**有效期**：微伴登录 cookie 约 7 天；企微 `open_sid` 为会话级 cookie。
若报 `40058` / `createOpenChatSession 未返回 sid`，重跑一次本脚本即可。

### 2. 看某员工有哪些会话

```bash
python wb_staff_export.py --staff "智泊AI-俏俏班主任老师" --list-sessions
```

### 3. 导出

```bash
# 最近 20 个客户会话，每会话最多 200 条
python wb_staff_export.py --staff "智泊AI-俏俏班主任老师" --sessions 20 --msgs 200

# 全部会话（1222 个，耗时较长）
python wb_staff_export.py --staff "智泊AI-俏俏班主任老师"

# 只导出 2026-09-01 之后
python wb_staff_export.py --staff 俏俏 --since 2026-09-01

# 群聊 / 同事会话
python wb_staff_export.py --staff 俏俏 --session-type room
```

`--staff` 支持全名、部分名字（唯一匹配时）、或 `staff_ext_id`。

### 4. 输出结构

```
导出/<员工名>/
├── 汇总.md          # 会话索引 + 统计表
├── 消息明细.jsonl   # 每条消息一行 JSON（可直接喂给 S2 打分 / S1 落库）
└── sessions/
    ├── 01_张利群.md
    └── ...
```

`消息明细.jsonl` 字段：
`staff_id, staff_name, session_id, session_name, msg_id, direction, time, time_str, type, msgtype, from_name, content`

**断点续传**：每个会话完成即写入 `.state.json`，中断后重跑会跳过已完成会话；
要强制重跑加 `--no-resume`。

## 五、性能实测

| 规模 | 结果 | 耗时 |
|---|---|---|
| 5 会话 / 176 条 | 正文命中 **176/176** | 数秒 |
| 20 会话 / 793 条 | 正文命中 **793/793** | **61 秒** |

≈ 3 秒/会话（含微伴消息翻页）。相比早期「每会话开一次浏览器」快一个数量级。

## 六、注意事项

- **凭据即权限**：`.cache/ww_bootstrap.json` 与 `.workbuddy/tmp/` 内含 cookie，
  等同于登录态，**不要提交 git、不要外发**。
- 导出的聊天记录含**客户个人信息**，注意留存与使用合规。
- 本链路走的是企微官方组件的接口，与微伴 OpenAPI 是两条独立通道；
  **微伴侧那个「正文为 null」的问题依然存在**，本工具是绕行方案。
- 群聊会话（`room`）企微侧通常不允许存档，可能拿不到正文。
