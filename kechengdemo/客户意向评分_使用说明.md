# 客户意向评分系统 · 使用说明

> 对应《客户意向识别系统需求文档.md》v1.0 §5 评分规则、§9.3–9.5 数据模型。
> 交付日期：2026-10-13

---

## 一、一句话定位

按需求文档的评分规则，把「规则引擎 + 大模型 + 人工复核」做成一个**稳定、可靠、可评估、可观测**的评分智能体：

- **正分**（加分项合计）→ 自动回写微伴「添加客户评分」接口
- **负分**（扣分项）→ 不直接生效，进入后台「负分复核」页，由工作人员确认/修正/驳回

---

## 二、评分流程（每个「员工—客户」关系）

```
① 选候选    有足够消息，且（无评估 / 有新消息 / 规则版本变化）才重评
② 组输入    规则表 + 近 60 条消息 + 规则引擎事实（连续 48h 未回复等）
③ 大模型    结构化输出命中的加分/扣分项（含证据）
④ 校验      rule_id 与分值合法性校验，非法项丢弃并留痕（invalid_items）
⑤ 规则引擎  补充硬指标扣分项（48h 未回复）；引擎专属规则不允许模型判定
⑥ 本地计分  rules.py 算总分与等级（模型不给总分，需求 §6.3）
⑦ 落库      customer_intent_assessment
⑧ 分流      正分 → 回写微伴；负分 → 人工复核队列
```

### 分工边界（需求 §5.5）

| 谁 | 管什么 |
|---|---|
| 规则引擎 | 连续 48h 未回复、候选筛选、水位判断、总分/等级计算 |
| 大模型 | 语义类加减分识别、证据提取、客户画像、销售策略 |
| 人工 | 负分项确认/修正/驳回、规则修改、回写开关 |

---

## 三、稳定性 / 可靠性 / 可评估 / 可观测

| 特性 | 实现 |
|---|---|
| 稳定 | 大模型与微伴接口均带指数退避重试；单会话失败不阻塞整体 |
| 可靠 | 总分一律本地计算；命中项合法性校验；引擎规则防模型越权重复扣分 |
| 幂等 | 回写 `UNIQUE(assessment_id)` 一次评估只写一次；消息/评估可重放 |
| 可评估 | 人工复核结果与 AI 结果落库比对，指标页给出「一致率」 |
| 可观测 | `scoring_run` 记录每次运行（会话数/评分数/复核数/回写数/LLM 调用与失败/用时）；`audit_log` 留痕所有人工操作 |
| 可追溯 | 每条评分保留规则版本、逐项证据消息、置信度、分析时间 |

## 四、数据表（PostgreSQL 5433 / weiban_chat）

| 表 | 说明 |
|---|---|
| `scoring_rule` | 规则版本化（rule_version + rule_id + score 唯一），由 `rules.json` 初始化 |
| `customer_intent_assessment` | 每次评分一条：总分/等级/逐项加减分/画像/策略/置信度/规则版本 |
| `score_writeback` | 回写微伴的幂等与审计（mode/status/errcode/errmsg/response） |
| `negative_review` | 负分人工复核队列（pending 未打分 / done 已完成 / ignored 已忽略） |
| `scoring_run` | 评分任务运行记录 |
| `audit_log` | 人工操作留痕（提交打分/改状态/切回写模式） |
| `app_setting` | 运行时设置（优先于 .env，前端可改） |

## 五、前端页面

### 评分中心 `/#/score`
- 启动评分（员工范围 / 会话上限 / 最少消息数 / 强制重评）
- 微伴评分回写模式切换（演练 / 真实写入）与定时评分设置
- 指标看板：已评客户、待复核、已完成复核、回写成功/演练、平均分、人工与 AI 一致率
- 等级分布、当前任务进度、评分结果列表（筛选/分页/详情抽屉含逐项证据）
- 运行记录表

### 负分复核 `/#/review`
- 状态标签页：全部 / **未打分** / **已完成** / **已忽略**（带计数）
- 筛选：员工、客户/员工名称、日期区间
- 详情：AI 扣分依据（含证据）+ 近期聊天记录气泡
- 人工打分：勾选确认成立的扣分项（分值可微调）、备注、处理人 → 提交后状态变「已完成」
- 也可「标记已忽略」「退回未打分」；每次操作写审计日志
- 指标：人工确认扣分与 AI 判定的一致性实时提示

## 七、配置（.env）

```ini
SCORE_WRITEBACK=dry_run          # live=真实写入 / dry_run=只记录 / off=关闭
SCORING_INTERVAL_MINUTES=0       # 定时评分（分钟，0=关闭）
SCORING_MAX_SESSIONS=200         # 单次最多会话数
SCORING_MIN_MESSAGES=4           # 少于此消息数不评
SCORING_FETCH_TAGS=false         # 是否拉取微伴客户标签作为事实（较慢）
SCORING_SLEEP_MS=0               # 大模型调用间隔（限流）
```

以上均可在前端「评分中心」运行时调整（`app_setting` 表优先）。

## 八、⚠️ 上线前必读：微伴评分回写

微伴「添加客户评分」接口（`POST /open-api/external_user/score/add`）：

- `score` 必须为 **大于 0 的整数**（否则错误码 20215）→ 因此只回写**加分合计**，负分走人工
- 接口对同一客户是**覆盖**还是**累加**语义，文档未说明 → **默认演练模式（dry_run）**：
  只把「本应写入的分值」记录在 `score_writeback` 表，不真改微伴数据
- 确认覆盖语义后，在「评分中心 → 微伴评分回写」切到「真实写入」即可；
  每次切换都会写 `audit_log`

**回写目标 id**：已实测微伴客户 id（`external_user_id`）即会话里的 `target_id`
（`wmgiz...`/`wogiz...` 格式），`staff_id` 直接用会话的员工 id。
