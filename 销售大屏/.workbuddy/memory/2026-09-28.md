**踩坑记录（重要）**
1. **Flask 热重载不可靠**：debug 模式下改了 app.py 后 reloader 未真正重启，导致新路由 404。
   改完后端路由/配置后，**务必手动重启服务**再验证。
2. **指标卡高亮不生效**：`startSpotlight()` 原本在 `init()` 里调用，此时 KPI 的 DOM 还没构建，

3. **地图多一个 canvas**：effectScatter 设了 `zlevel:2`，ECharts 会为它单独建一层 canvas，
   所以 5 个图表有 6 个 canvas，属正常现象。
4. **地图系列用 geoIndex**：`geo` 组件提供坐标系，`series.type='map'` 靠 `geoIndex:0` 复用；
   同时给 geo 设了兜底 areaColor，即使分级设色异常也能看到地图轮廓。

## 任务 15：大屏右下角 AI 悬浮机器人

**新增文件**：`templates/dashboard.html`（追加机器人 DOM）、`static/js/robot.js`、
`static/css/dashboard.css`（追加机器人样式）；`app.py` 新增 `POST /api/ai/brief`

**⚠️ 最大的坑：DeepSeek 思考模式不支持 `tool_choice`**
- 报错：`400 Thinking mode does not support this tool_choice`
- 影响：**LangChain `create_agent(response_format=...)` 完全不可用**，
  因为它内部靠强制 `tool_choice` 实现结构化输出
- 解法：改用 **「工具 artifact 回传 + 严格文本格式 + 后端正则解析」**
  - 提示词要求固定格式：`结论：xxx` / `依据：` + `- 条目`
  - `_parse_brief()` 用正则解析，解析失败时降级为「整段作为结论」，不丢信息

**「实际使用的 Pandas 工具」怎么做到真实可信**
- 工具改用 `@tool(response_format="content_and_artifact")`，返回 `(content, artifact)`
- artifact 里带**本次真实执行的 pandas 表达式**（在 `_apply_filters` 里拼筛选条件、
  在各分支拼聚合链），由 `_extract_trace()` 从 ToolMessage.artifact 读出并去重
- **不是模型自述**，是可逐字核对的真实执行路径
- 注意：`tool.invoke()` 只返回 content，artifact 只在 agent 消息轨迹里以 `ToolMessage.artifact` 暴露；
  直接调底层函数要用 `tool.func(...)` 才会返回元组

**机器人的「闲聊不走工具」**
- `ask_brief()` 返回 `usedTool`，前端据此决定渲染方式：
  - `usedTool=true` → 三段式（结论块 + 依据列表 + Pandas 代码块）
  - `usedTool=false` → 纯文本气泡，不显示依据/Pandas

**实测（全部通过）**
- CT 探针验证：入口球在右下角 24px/24px；点开→面板展开、fab 隐藏、状态「已就绪」
- 发送后：加载点 + 轮换文案「正在解析问题…」、发送按钮禁用、状态「思考中…」
- 回答渲染：结论 + 4 条依据 + 1 条 Pandas 表达式，消息区可滚动且自动滚到底
- 最小化：面板收起、fab 恢复、消息保留
- 闲聊「你好，你是谁？」：纯文本气泡，结论/依据/Pandas 块均为 0
- 无 CSV：工具返回「无数据」，结论为「系统里还没有上传销售数据文件」
- 数值核对：京东自营利润 85,084.12 / 抖音直播间 76,029.61 / 小红书 69,005.40
  与 pandas 独立核算**完全一致**

**新增路由**：`POST /api/ai/brief`

**注意**：机器人放在 `.stage` 内（随大屏等比缩放），
z-index 60 高于「暂无数据」遮罩，所以无数据时也能打开问问题。
