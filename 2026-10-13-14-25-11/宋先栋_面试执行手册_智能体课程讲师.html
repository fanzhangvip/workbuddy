Interview Playbook

面试执行手册 · 智能体课程讲师

候选人：宋先栋（男 · 本科 · 3 年） 现职：大模型开发工程师 应聘：智能体课程讲师

一、先看结论：这是一场"错位"面试

他的简历技术含量远超岗位要求（LangGraph 多 Agent、RAG 全链路、MCP、量化成果齐全）， 但简历里没有一个字提到 Coze / Dify / WorkBuddy（JD 硬门槛）， 没有一个字提到教学、教程、社群、作品（这是"讲师"的立身之本）。 所以这场面试的重心不是"考他会不会做智能体"，而是回答三个问题：
这场面试只需回答 3 件事：
  1. 他会不会用 Coze / Dify / WorkBuddy？——简历零证据，是 JD 硬门槛
  2. 他能不能把技术讲成小白听得懂的话？——深技术背景最易踩"术语碾压"的坑
  3. 他有没有教学 / 内容作品？——讲师岗没有作品，技术再好也要打问号

预判：他的画像更像 进阶 / 代码模块讲师 或 课程技术顾问， 而不是零基础入门课的主讲。能不能推荐，取决于上面三个问题的答案。

三、面试流程设计（建议 60 分钟 · 复面为主）

建议先做 15 分钟电话预筛（清掉学历/地点/Coze 经验等硬伤），再进 60 分钟复面。复面按下面节奏推进：

  • 0–5 min
    开场 + 职业动机
    先问"为什么从开发转讲师"——这是他的核心拐点，也决定后面所有判断的基调。
  • 5–18 min
    技术深挖 + Coze/Dify 缺口探测
    挑最复杂的项目深挖（考转译），再直接问零代码平台使用经验。见 Q1–Q4。
  • 18–33 min
    ★ 即兴试讲 + 教学能力深挖（重头戏）
    3 分钟限时试讲，决定录用与否。见 Q8–Q11。
  • 33–45 min
    业务与提效案例深挖（验数据）
    挑 1–2 个简历数字当场归因，并测试跨行业迁移。见 Q5–Q7。
  • 45–53 min
    内容产出 / 产品思维 + 软素质
    强制索取作品；设计第一节课；压力测试。见 Q12–Q18。
  • 53–60 min
    候选人提问 + 收尾
    看他问什么——问课程效果、学员反馈的，多半是真想做教学；只问薪资工时的，动机存疑。

四、问题清单（按维度定制，含追问与评分锚点）

维度一 · 智能体技术能力（权重 30%）

Q1　挑你最复杂的项目（知学智慧校园助手）讲讲转译初筛
考察点
项目是否本人主导、能否把设计讲清楚（讲师必须能复述自己的东西）。重点不是技术深度，是他能不能讲明白。
追问
① 为什么用 LangGraph 手写状态图，而不是用现成平台？② 那个"8 节点批改流水线"，如果给一个完全不懂技术的老师讲清楚，你会怎么讲？③ 过程中最大的坑是什么，怎么解决的？
5 分：能讲清设计权衡 + 真实踩坑 + 效果，且能用大白话说清架构。　3 分：能讲功能，讲不出"为什么"。　1 分：只报技术名词，问细节就卡。
Q2　Coze / Dify / WorkBuddy 你用过吗？做过几个？★ 硬门槛
考察点
JD 硬门槛：Coze 或 Dify 独立完成 3 个以上可展示项目。他简历零提及，必须当面确认。
问法
"你的项目都是自己写代码（LangGraph / LangChain）。我们这门课主要教非技术的人用 Coze 和 Dify 搭智能体。这两个平台，还有 WorkBuddy，你实际用过吗？"
追问
若没用过：① 你打算多快上手并教别人？② 你既然能做代码方案，怎么看待零代码平台？什么场景该用零代码、什么场景必须上代码？
5 分：用过且有可展示作品，能清晰讲清"零代码 vs 代码"的适用边界。　3 分：用过或了解，愿意快速补齐。　1 分：完全没碰过，且觉得"没必要/看不上"。
注意：这是能力缺口不是态度缺口。没用过但学习意愿强、有清晰上手路径，可给 3 分并列入培养观察；否则这门课他教不了主体部分。
Q3　用 60 秒，把 RAG 讲给一个完全不懂技术的人听转译测试
考察点
这是他最熟的技术，正好测"降维"能力——越是熟的越容易不自觉堆术语。
追问
再用一个生活类比讲讲"向量检索"是什么。
5 分：类比贴切、全程无术语、60 秒内说清。　3 分：能讲清但会蹦术语。　1 分：直接上 embedding、余弦相似度。
Q4　你简历写了 MCP，用大白话讲 MCP 是干嘛的转译测试
考察点
同上，考把抽象协议讲成人话的能力。
5 分：用一个"USB 接口 / 万能插座"级别的类比讲清。　1 分：背协议定义。

维度二 · 业务理解与提效经验（权重 25%）

Q5　"老师"这个岗位，每天最耗时、最重复、最痛的 3 件事是什么？验真懂业务
考察点
他是开发者视角，痛点可能来自需求方二手转述。要分辨"真了解"还是"听来的"。
追问
① 这些痛点是你自己观察到的，还是需求方告诉你的？② 你去过学校现场吗？见过老师实际怎么改作业吗？
5 分：能说出具体到"粒度"的细节（一份作文批改几分钟、老师最烦重复写评语）。　3 分：知道大概，细节含糊。　1 分：全是想象。
Q6　"批改耗时下降 50%"，这个 50% 具体怎么算出来的？★ 验数据
考察点
简历数字真实性。挑 1–2 个数字当场归因即可判断整体可信度。
追问
① 基线是多少（原来每份几分钟）？② 谁测的、样本多大？③ 老师真实反馈是什么？④ 有没有失败 / 被弃用的时候？
5 分：能说清测算口径，且主动讲反面案例。　3 分：大概记得。　1 分：说不清、含糊带过。
红旗：所有数字都是"提升 XX%"，但问"怎么来的"就绕开。
Q7　课程要覆盖 HR、财务、律师、老师。你只有教育经验，明天让你讲一节"财务自动对账"，你怎么拆这个场景？迁移能力
考察点
能不能从"自己那一摊"迁移到陌生行业——这是讲师能否覆盖多行业的命门。
追问
你用什么方法快速摸清一个陌生岗位的痛点？（听有没有方法论）
5 分：有方法（访谈 + 流程拆解 + 找高频重复环节 + 定优先级）。　3 分：愿意学但没方法。　1 分：只会讲自己做的教育项目。

维度三 · 表达与教学能力（权重 25%）—— 本场决定性维度

Q8　【必考 · 一票否决级】3 分钟，给一个完全不懂技术的 HR 讲明白"什么是智能体"。现在开始★ 试讲
规则
不给准备时间、不许打草稿、限时 3 分钟。假装对面坐着一个连 API 都不知道的 HR。
考察点
这是讲师最核心的能力，也是他"深技术背景"最大的风险点。
追问
讲完后追一句：如果你讲完对方还是皱眉，你会换个什么说法？
5 分：有生活类比（如"带一个新来的实习生"）、逻辑顺、全程无术语、小白真能听懂。　3 分：能讲清但有点绕 / 不自觉蹦术语。　1 分：术语堆砌，自己讲得嗨。
红旗：开口就是"智能体是基于大模型的 Agent 框架，通过 Planning、Memory、Tool Use…"——直接判 1 分。
Q9　你以前教过别人吗？带新人、社群分享、写教程都算教学经历
追问
能现场给我看一个作品链接吗？（公众号 / B 站 / 知乎 / Coze 主页 / 视频都行）—— 强制索取，看不到实物就按"无作品"计。
5 分：有真实教学经历 + 学员反馈 + 可展示作品。　3 分：零星分享过。　1 分：从没教过。
Q10　学员学完说"我还是不会"，你会怎么办？学员导向
5 分：先从学员视角找卡点 → 给具体解法 → 反哺课程改进。　1 分：觉得"是学员没认真听"。
Q11　你技术这么强，学员连"什么是 API"都不知道、反复问你，你会不耐烦吗？★ 同理心
考察点
正对 JD 避坑项"技术很强但讲不清楚 / 习惯用术语碾压新手"。
追问
那你现在就把"API"讲给一个 HR 听，怎么讲？
5 分：真诚 + 立刻给出贴切类比。　1 分：流露"这都不会"的不耐烦。

维度四 · 内容产出与产品思维（权重 10%）

Q12　写过教程 / 公众号 / 知乎 / B 站吗？有作品吗？内容产出
追问
① 有多少人看过 / 学过？② 你怎么组织结构？③ 根据反馈改过什么？
5 分：有高质量作品、有人看、有迭代。　1 分：从没写过任何教学内容。
Q13　如果让你设计这门课的第一节课，你会怎么设计？目标是什么？产品思维
5 分：第一节课就让学员做出一个能跑的东西、从"场景"而非"功能"切入、先给成就感。　1 分："把所有功能讲一遍，体系化教学"——这是讲师思维，不是产品思维。
Q14　怎么判断一门课上得好不好？效果意识
5 分："学员学完真的用起来了吗、真的提效了吗"。　1 分：只看"完课率"。

维度五 · 软素质与文化匹配（权重 10%）

Q15　最近在学什么新 AI 工具？从哪知道的？用起来了吗？学习力
5 分：有具体工具 + 自己的信息渠道 + 实际使用体验。　1 分：说不出来。
Q16　学员问了你也不会的问题，你怎么办？责任心
5 分：坦诚说不知道 + 承诺时间 + 真的追着回复。　1 分：瞎编，或"你自己百度"。
Q17　【必问】你为什么不想做开发了，想做讲师？★ 核心动机
考察点
这是他从技术转教学的核心拐点。有没有一个真实的故事（比如自己用 AI 提效后想分享给更多人），比"我看好 AI 教育赛道"真诚得多。
5 分：有真实故事和热情，讲得出"教人学会"的成就感。　1 分：只因为"行业火"或"讲师比开发轻松"。
Q18　【压力测试】你简历全是开发成果、也没提 Coze/Dify，我们这门课是教零基础职场人的。你凭什么能教？★ 抗压
考察点
面对质疑的态度——是防御，还是坦诚 + 给方案。
5 分：承认短板 + 给出清晰的补齐路径 + 讲清自己不可替代的价值（如能讲清"什么时候零代码不够用"）。　1 分：辩解、绕开，或贬低零代码平台。

五、怎么考核：6 个验证手段

  1. 即兴试讲（Q8，最高权重）——单独打分。讲师岗不看试讲，其他都是空谈。
  2. 作品现场展示（Q9/Q12）——强制。看不到实物，内容产出维度直接判 ≤2 分。
  3. 简历数字抽查（Q6）——挑 1–2 个"X%"当场归因，判断数据是真是假。
  4. 转译测试（Q3/Q4/Q11）——让他把 RAG、MCP、API 讲给"小白"听，现场模拟学员。
  5. 教学产品化小测——现场让他出 1 道课后作业题 或设计 1 个小案例，看有没有把知识变成可交付内容的能力。
  6. 信息核实——学历 / 工作时间线、2026/08 离职原因、广州→长沙意愿、投递岗位为何是"AI 产品经理"。

六、评分与决策规则

按《面试评估表》权重加权（技术 30% / 业务 25% / 表达教学 25% / 内容产出 10% / 软素质 10%），但先过三条红线：

红线触发条件处理
红线 1即兴试讲（Q8）< 3 分不通过——技术再强也不行，试讲是讲师岗的生命线
红线 2无任何内容 / 教学作品，且无教学经历内容产出维度封顶 ≤2 分，整体降为"待定"
红线 3Coze / Dify 零经验，且学习意愿弱 / 看不上零代码不通过或转为技术岗评估
加权总分建议结论
≥ 4.0强烈推荐　试讲优秀 + 有作品 + 愿补 Coze/Dify
3.5 – 3.9推荐　可先定位为"代码 / 进阶模块讲师"或带教培养
3.0 – 3.4待定　给一道试讲作业题（录 5 分钟视频）再评
< 3.0不推荐
最终判断建议：不要拿"技术强"直接兑换"能当讲师"。他极可能是 "进阶 / 代码模块讲师"或课程技术顾问 的好料， 但零基础入门课主讲的三个必要条件（会 Coze/Dify、会讲人话、有教学作品），简历上一个都没证明。 面试结论请严格绑定试讲表现和作品实物。

七、会前预筛查清单（先发 HR / 猎头，清掉硬伤）

  1. 是否实际用过 Coze / Dify / WorkBuddy？做过几个可展示的智能体？
  2. 有无 教学 / 内容作品链接？（公众号、B 站、知乎、Coze 主页、课程视频）
  3. 现居广州，是否接受 长沙？期望薪资？
  4. 2026/08 离职原因？现在状态（在职/待业/接活）？
  5. 学历时间线：2023/08 入职时是否仍在读？是实习还是全职？
  6. 投递岗位名为"AI 产品经理"，本人真实意向是 讲师 / 产品 / 开发 哪一个？
