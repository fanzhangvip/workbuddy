### 4.1 CLI 契约（1 条）：测试机制无法对任何正确实现通过

修好之后，降级路径会**正常启动 Web 服务并常驻**，于是该测试的 `subprocess.run(timeout=30)` 抛 `TimeoutExpired`，**根本走不到它自己的断言**（`"AttributeError" not in stderr`）。
修复前它失败是**真信号**（确实是 AttributeError）；修复后它失败变成**机制问题**。

- 需要的裁决：**(a)** 测试改成只看前几秒输出、或 **(b)** 实现提供一个明确的「自检后退出」开关（例如读某个环境变量后只校验参数不真正 serve）。
- 我倾向 (a)，但**这是你的测试，我不改**。

### 4.2 配置热重载（3 条）：测的是一套本项目不存在的 API

三条都调用：

```python
config_loader.load(str(config_file))        # 模块级函数，读 JSON 文件
config_loader.ConfigLoader(str(config_file))  # 单参构造
```

而本项目实际是：

```python
ConfigLoader(env_file, cipher, *, db_provider=...)   # 三个参数，配置源是 env.py + 数据库
loader.load()                                         # 实例方法
```

**本项目没有「JSON 配置文件」这个概念**，所以这不是实现缺陷，而是**契约分歧**。
而且测试文件自身矛盾：注释里写「具体注册接口名由你根据 loader 的真实 API 调整」，文件头写「WorkBuddy 不得修改」。

- 需要的裁决：是想让配置源**改成 JSON 文件**（那是一次真实重构，请确认），还是这三条测试按真实 API 重写？
