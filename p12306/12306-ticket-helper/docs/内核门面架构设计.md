# 内核门面 · 架构设计与接口规格

> 顺序要求：**先定架构 → 再定接口/协议/参数 → 跑通流程 → 最后填实现细节**。
> 本文是前三步的产物；第四步（实现细节）只在本文的约束内填。
> 任何与本文冲突的实现都算设计缺陷，要先改本文。

---

## 一、目标与非目标

**目标**：让「候补请求体怎么拼」这一层可以**按接口灰度切换到上游实现并一键回退**，
且**默认行为零变化**。

**非目标**（明确不做，避免范围失控）：

- ❌ 不把传输层（风控识别 / 限速 / 重试 / 会话 / 扫码登录）做成可切换。
  上游对这几项是**零实现**（grep 命中 0），换过去会同时失去登录与风控识别。
- ❌ 不引入 `testerSunshine/12306` 的整棵依赖树（`config/` 22 处、`TickerConfig` 11 文件、
  `wrapcache` 7 处、`myException` 6 处，且需 TF1.14）。
- ❌ 不动 `TaskConfig` / 引擎 / UI 的任何接口。

## 二、分层与依赖方向

```
┌──────────────────────────────────────────────────────────────┐
│ 表现层    desktop_ui/            web/static/*(app.js/css)      │
├──────────────────────────────────────────────────────────────┤
│ 应用层    runtime/context.py      scheduler/                   │  组装 · 生命周期
├──────────────────────────────────────────────────────────────┤
│ 业务层    grab/  standby/  order/  query/  account/  notify/    │  不认识 12306 协议
├──────────────────────────────────────────────────────────────┤
│ 协议门面  inter/api.py  ← 业务层唯一认识的协议入口              │  收口
├──────────────────────────────────────────────────────────────┤
│ 内核门面  kernel/       ← 【本次新增】可切换的「请求体构造」     │  ← 灰度点
├──────────────────────────────────────────────────────────────┤
│ 协议实现  inter/urls.py  inter/parser.py  kernel/*_builder.py  │
├──────────────────────────────────────────────────────────────┤
│ 传输层    inter/base.py::HttpClient（风控识别 / 限速 / 重试）    │  ← 不可切换
└──────────────────────────────────────────────────────────────┘
```

**依赖方向铁律（可机器检查）**

| 规则 | 为什么 |
|---|---|
| `kernel/` **不得** import `inter/` | 否则门面与实现绑死，切换失去意义；且会形成环 |
| `kernel/` 只允许依赖 `ticket_helper.errors` + 标准库 | 保持门面可独立测试 |
| `inter/api.py` 可以 import `kernel/` | 上层依赖下层接口，方向正确 |
| `business` 层（grab/standby/order/query/account）**不得** import `kernel/` | 灰度是「协议细节」，不该泄漏到业务语义里 |

> 第 4 条是本次的关键约束：业务层只写 `user.api.confirm_hb(...)`，
> **它不知道也不该知道**当前用的是哪套请求体。切换是部署配置，不是业务分支。

## 三、接口规格（先定接口，后定实现）

### 3.1 唯一对外的取值函数

```python
# ticket_helper/kernel/__init__.py

ENV_VAR: str = "TICKET_HELPER_KERNEL_STANDBY_PAYLOAD"         # 唯一处定义
DEFAULT_BACKEND: str = "testerSunshine"                        # 决策 B：上游实现
ROLLBACK_BACKEND: str = "self"                                 # 一键回退名

def available_backends() -> tuple[str, ...]: ...
def get_standby_payload() -> StandbyPayloadBuilder: ...
```

**契约**：

1. `get_standby_payload()` 每次调用都重新读环境变量（便于测试与热切换），**不缓存**。
2. 非法取值 → 抛 `ConfigError`，**快速失败**，不静默回退。
   理由：静默回退会把「我明明切了 upstream」变成一句无法查证的猜测。
3. 默认后端是 `testerSunshine`（决策 B）；**回退后端 `self`** 的输出必须与改造前
   **逐字节一致** —— 「一键回退真的能回到从前」是这条门面的安全底线。
4. `available_backends()` 是可选后端名的唯一下发点，界面/脚本不许硬写字符串。

### 3.2 Protocol

```python
@runtime_checkable
class StandbyPayloadBuilder(Protocol):
    name: str                                    # 必须 == 注册表里的键

    def build_passenger_info(self, passengers: Sequence[Mapping[str, Any]]) -> str: ...

    def confirm_hb_params(
        self, *,
        passenger_info: str,
        jz_param: str,
        train_no: str,
        seat_code: str,
        if_receive_wseat: str = "N",
        realize_limit_time_diff: int = 1440,
    ) -> dict[str, Any]: ...
```

**为什么只有两个方法？**
候补七步的其余六步（`chechFace` / `getSuccessRate` / `submitOrderRequest` /
`passengerInitApi` / `getQueueNum` / `queryQueue`）经逐接口对照，
**请求体与上游一致**，没有可切换的内容。**不抽用不上的东西** ——
多抽一层就多一处没人验证的抽象。

### 3.3 参数语义表（每个参数的来源与去向必须写死）

| 参数 | 类型 | 含义 | **来源** | 谁使用 |
|---|---|---|---|---|
| `passengers` | `Sequence[Mapping]` | 乘车人（来自 `getPassengerDTOs`，含 `allEncStr`） | 业务层传入 | F3（段数分歧） |
| `passenger_info` | `str` | 已拼好的乘客串 | `build_passenger_info` 的返回 | 进 `passengerInfo` 字段 |
| `jz_param` | `str` | 候补截止时间，形如 `2026-10-01#19#00`；**未知时为空串** | ④ `passengerInitApi` 响应的 `jzdhDateE`+`jzdhHourE` | **F2** |
| `train_no` | `str` | 官方**内部**车次号（形如 `5l000G61020A`） | ② `getSuccessRate.data.flag[0].train_no`，回退 `ticket.train_no`/`train_code` | **F1** |
| `seat_code` | `str` | 官方席别编码（`O`/`M`/`9`…） | `SEAT_CODE` 查表，**由调用方解析好** | `hbTrain` |
| `if_receive_wseat` | `str` | 是否接受无座（`Y`/`N`） | 调用方参数 | **F4** |
| `realize_limit_time_diff` | `int` | 兑现时限（分钟），默认 1440 | 调用方参数 | **F4** |

**参数设计原则**：门面**只接原始值**，不接 `ticket` / `session` 这类大对象。
理由：大对象会把 `inter/` 的类型泄漏进门面，切换后端时就得同时切换类型。

### 3.4 返回值规格

`confirm_hb_params` 返回**待提交的表单字典**（`dict[str, Any]`），
不含 URL、不含请求头 —— URL 与 Referer 属于传输层，不在这条门面上。

`build_passenger_info` 返回**非空字符串**；乘车人缺少 `allEncStr` 时抛 `InterError`
（该守卫与上游写法无关，属安全底线，两个后端都必须有）。

## 四、流程（先跑通，再填细节）

### 4.1 端到端时序（切换点只有一处）

```
standby/engine.py
  └─ user.api.confirm_hb(passengers, seat_codes, ticket, ...)      ← 业务层不变
        │
        ├─ ① inter/api.py::check_hb_face          （请求体与上游一致，不切换）
        ├─ ② inter/api.py::get_hb_success_rate    → 记下 flag[0].train_no   【F1 数据来源】
        ├─ ③ inter/api.py::submit_hb_request      （一致，不切换）
        ├─ ④ inter/api.py::init_hb_passengers     → 记下 jzdhDateE/jzdhHourE 【F2 数据来源】
        ├─ ⑤ inter/api.py::check_hb_queue_num     （一致，不切换）
        │
        ├─ ★ kernel.get_standby_payload()          ← 唯一的切换点
        │      ├─ .build_passenger_info(passengers)        【F3】
        │      └─ .confirm_hb_params(...)                  【F1/F2/F4】
        │
        └─ ⑥ inter/api.py::_hb_post(HB_CONFIRM, params)    ← 传输层不切换
        └─ ⑦ inter/api.py::query_hb_queue                  （一致，不切换）
```

### 4.2 「跑通」的判定（外部可观察）

| 阶段 | 判定信号 | 谁给 |
|---|---|---|
| 接口层跑通 | `python scripts/kernel_diff.py` 能打印两条后端的请求体差异表 | 离线，可复跑 |
| 流程跑通 | mock 端到端：候补单被 mock 接受（`flag:true`），订单里出现这一趟 | 离线，可复跑 |
| 契约成立 | 撤掉 `kernel` 实现 → 对应测试**必须变红** | 离线，可复跑 |
| 默认无异动 | `self` 后端下，`confirmHB` 收到的表单与改造前逐字节相同 | 离线，可复跑 |
| 真机结论 | ④ 的真实响应体（`jzdhDateE` 是否存在）、② 的 `train_no` 是否等于本地值、候补能否提交成功 | **仅真机**，由使用者跑 |

**前四项本轮完成；第五项不在本轮范围内，但本轮必须把它的探针准备好。**

## 五、F1–F4 的处置决定（2026-09-29 已按决策 B 定案）

| 编号 | 回退后端（`self`） | **默认后端（`testerSunshine`）** | 动作 |
|---|---|---|---|
| F1 | `ticket.train_no or ticket.train_code` | `getSuccessRate` 返回的 `train_no` | 两条都实现；**默认不变**；把两者差异打 INFO 日志 |
| F2 | `jzParam = ""` | `jzParam = "<date>#<HH>#<MM>"` | 同上；**捕获并打印真实响应**，让证据可积累 |
| F3 | 6 段（含 60 岁位） | 5 段 | 两条都实现；**默认 6 段不变** |
| F4 | 10 个字段 | 4 个字段 | 两条都实现；**默认 10 个不变** |

**决策（2026-09-29）**：需求方选择 **B —— 候补改用上游 `testerSunshine/12306`**
（因为 `pjialin/py12306` 没有候补），因此 **默认后端改为 `testerSunshine`**，
`self` 保留为**一键回退**（`TICKET_HELPER_KERNEL_STANDBY_PAYLOAD=self`）。

⚠️ **但要分清两件事**：
- 「用上游代码」是**来源**问题 —— 已由决策 B 解决；
- 「四处分歧谁对」是**正确性**问题 —— **仍然没有真机证据**，不由决策解决。

所以本轮同时交付了**真机探针**：`TicketApi._log_hb_evidence` 在每次候补尝试时
把判定 F1/F2 所需的证据打到 **INFO**（官方车次号 vs 本地、`jzParam`、
`passengerInitApi` 的返回键）。切到上游不等于判对了 —— 判对只能靠真机信号
（对照报告 §4.3 的 B 级）。

## 八、验收契约（每条都要能「撤掉实现就变红」）

| # | 断言 | 防的是哪种真实故障 |
|---|---|---|
| C1 | `kernel/` 不 import `inter/` | 门面与实现绑死 → 切换失效 |
| C2 | 业务层不 import `kernel/` | 灰度泄漏进业务语义 → 换配置等于改逻辑 |
| C3 | `DEFAULT_BACKEND == "testerSunshine"` 且回退名在册 | 默认后端被无声改掉（= 换行为） |
| C4 | `self` 后端输出 == 改造前的字面量 | 「回退能回到从前」只是口头承诺 |
| C5 | `testerSunshine` 后端输出 == 上游原件（跑 `--check` 逐字比对） | 「用了上游代码」只是口头承诺 |
| C6 | 两个 `name` 与注册表键一致 | 注册名与自报名两处漂移 |
| C7 | 非法 `ENV_VAR` 抛 `ConfigError` | 静默回退 → 「我明明切了」无法查证 |
| C8 | `_hb_post` 收到的是门面产出的表单（切前/切后都验） | 门面写了但没接上（最常见的假实现） |
