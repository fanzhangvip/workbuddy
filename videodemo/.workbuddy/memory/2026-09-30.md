### 用户确认后已实现（第二批，测试 336 项全绿）

## 重要更正：bot 校验的真正原因（实测，推翻之前的结论）

本轮做了两个决定性实验（经 Clash `127.0.0.1:7897`，沙箱注入的代理变量先清掉）：

1. **JS 运行时对照**：不给运行时 / 给内置 qjs / 给 node —— **三者报错完全一样**，都是机器人校验。所以 JS 运行时**不是** bot 校验的成因（之前"修好 JS 运行时顺带解决 bot 校验"的结论不成立，那次成功只是出口 IP 不同或 YouTube 抽风）。
2. **客户端全扫**：13 个 `player_client` 全试 —— **全部机器人校验**（只有 `web_music` 报"视频不可用"，那是因为它只认音乐）。

真正的原因：**出口 IP 是机房地址**。`curl -x 127.0.0.1:7897 https://api.ipify.org` → `152.70.176.68`，`ip-api` 显示 `Oracle Cloud Infrastructure (eu-frankfurt-1), hosting=true`；这个 IP 也正是用户应用日志 `videoplayback` URL 里的 `ip=152.70.176.68`。YouTube 对机房 IP 一律要求验证。

- 结论：**换策略、换运行时都没用**，只能换住宅/原生 IP 节点、换网络，或补 cookie。文案已按此改写。
- 本机**没有任何浏览器 profile**（Chrome/Edge/Firefox/Brave 都没有），所以"从浏览器读 Cookie"在这台机器上无源可读，得用导出的 `cookies.txt`。

## 用户报"能播但没声音"：根因是 YouTube 对「整段」请求限速 100 倍

### 根因链（全部用数据坐实，别再靠猜）

1. 用户环境是 Clash Verge（`HTTPS_PROXY=http://127.0.0.1:7897`），解析与播放都必须走本地反向代理。
2. **播放内核一上来发的是 `Range: bytes=0-`（整段）**。代理原样转给 googlevideo →
   **源站按 ~15 KB/s 涓流**。对照实测（`tools/upstream_rate.py`）：
   `Range: bytes=0-` ≈ 15 KB/s、不带 Range ≈ 8 KB/s，而**有界区间** `bytes=0-1048575` ≈ **1649 KB/s**
   —— **差 100 倍**。所以这不是"代理慢"，是**源站对无上界请求故意限速**。
3. 音频流 129 MB，解析器要读媒体头 + 尾部索引（要 seek 到 `clen-1`）→ **14~20 秒才 LoadedMedia**，
   正好撞上 Qt 的 `custom network timeout: 20000ms` → 有时 `error -138` → `InvalidMedia` →
   降级"仅画面"（= 无声）。
4. 就算音频加载上了（21s），也已经落后画面 18s；旧同步逻辑每 3s 补一刀 seek，
   而 WebM 重定位要 5.6~7.2s → **刀刀相连，声音被永久按死在 seek 目标上** → 全程无声。

### 修法

- **`src/core/local_proxy.py`：向上游"分片"取数**。把无上界/超大区间的请求改写成
  `bytes=offset-(offset+8MB-1)` 的有界区间，依次取回、**只回一次响应头、正文多片续写**，
  客户端看到的仍是一个正常的 206/200。关键常量 `_SLICE_BYTES = 8MB`、`_FORCE_CLOSE = True`。
  纯函数 `parse_range()` / `total_from_content_range()` 便于单测。
  ⚠️ 退回普通转发的那条路径**必须把 `headers["Range"] = client_range` 放回去**（我漏过一次，
  被既有测试 `test_range_is_passed_through` 抓住：所有范围请求都被吞掉，200 != 206）。
  ⚠️ `date` 必须从 `_PASS_RESPONSE_HEADERS` 里去掉（`send_response()` 自己会发，会重复）。
- **`qt_backend` 同步逻辑三重保护**：一次只允许一刀在途（`_pending_target`）、
  超时 8s 停自动校正并 `extraAudioStalled` 上报、间隔指数退避。

## 追加一轮：**自动音画校正本身才是"听得见的毛病"来源**（推翻上一轮的判断）

用户报"没声音"修好后继续深挖，把两个播放器的 position 按秒打出来（`--debug`），
结论跟直觉相反，**下一轮别再"把阈值调小"当成修复**：

- 两路从同一次 `play()` 启动，声音那一路依然**恒定落后 270~600ms**（起播固有差；
  同一次运行内**一动不动**：实测过 372/392ms、592/272ms、432/272ms 三组，
  每次运行数值不同但组内恒定）。关掉自动校正连测 30 秒，偏差**一直钉在同一个数**上，不增大。
- 校正的代价是**声音重新定位 0.5~2s**（经代理每个上游请求 TTFB 就 ~0.5s，
  且**连接复用只能省 0.03s** —— 已实测，不是 TLS 握手问题，别去搞连接池）。
  这期间声音 position 停在原地 → 校正**自己制造出更大的偏差**：
  实测校正前 452ms → 校正后 992ms，然后每 3s 再来一刀，偏差在 **267ms↔1225ms**
  之间来回摆，声音被切成一秒一个台阶。**比不校正（恒定 400ms、完全不跳）差得多。**
- 所以：`_SYNC_TOLERANCE_MS` **回调到 1200**（= 固有差的两倍余量，正常播放一次都不校正，
  只有缓冲欠载这种秒级偏差才出手）；新增 `_sync_interval_ms` 指数退避
  （一刀没把偏差压下去就 ×2，封顶 30s，压下去了立刻回基准）。
- **踩出来的坑**：判定"这一刀还没生效"的余量原本**共用** `_SYNC_TOLERANCE_MS`，
  两个语义是反的（一个大表示"允许不同步"，一个要小表示"还停在原地"）。
  阈值一放大，偏差 400ms 就被误判成"seek 没生效"，8 秒后误报"已停止自动校正"。
  已拆出独立常量 `_SYNC_PENDING_EPS_MS = 120`，并有回归测试钉死。
- 修后实测：全程**一次校正都没有**，声音 position 每秒稳定 +1000ms 不冻结，
  seek 前后偏差分别恒定 432ms / 272ms。**连续、无跳音。**

### 残留（未解决，属已知限制）

- 那 270~600ms 的固有差还在。它来自"画面 play()→首帧 ≈0.5s、声音 play()→首声 ≈1.0s"
  这条管线延迟差。正中解的两种做法：①**mpv 单播放器**（原生音画同步，`audio-add` 命令，
  注意不是 `audio-file` 属性）；②让声音先起播、画面等它真的出声再起播（自适应，但会拖慢起播）。
  都没做——本轮收益已经拿到，改动风险大于收益。

## 17:30 前后 —— VPN / 代理设置化（用户新需求）

用户问"这个播放器是否可以使用 VPN，应该是可以在设置里面配置的才行"。

**结论：本来就支持，但设置里只有一个光秃秃的输入框，没法验证"生效没、通不通"。**
本轮把它做成一个能自己说明状态、能实测的区块（设置 → 网络 → VPN/代理）：

- **新模块 `src/utils/proxy_check.py`**（只读、无副作用）：
  - `sources()`：三个来源（设置 > 环境变量 > Windows 系统代理）的取值；
  - `describe_active()`：一句话说清当前生效的是哪条 + 播放侧会发生什么；
  - `check()`：**同一条地址直连一次、经代理一次**，对照给结论——
    "代理可用""走代理反而不通（查端口）""本机有网但代理通路不通（换节点）"、
    "两边都不通（本机没网）"分得清；502/503/504 单独指向"换节点"而不是"改端口"；
  - 直连探测**必须显式传 `{"http": None, "https": None}`** 压住环境变量，
    否则测到的不是"直连"（与 `local_proxy._upstream_proxies` 同一坑）。
- **设置面板**：VPN/代理组框 = 地址栏 + 「检测系统代理」一键填入 +
  「当前生效」实时状态（textChanged 触发）+ 「测试连通性」（后台线程 +
  QTimer 轮询取结果，不跨线程碰 Qt）。
- **`tools/vpn_check.py`**：命令行同款体检（退出码 0/1 可入脚本）。
- **selfcheck**：新增"VPN / 代理"段（只读不发请求，断网也能跑完）。
- 实测（本机 Clash 7897）：直连 YouTube 8s 超时、经代理 664ms HTTP 200，
  结论"代理可用：这条地址必须经代理，而经代理能访问"。
- **README** 新增「### VPN / 代理（设置 → 网络）」一节，讲清两种 VPN 模式：
  TUN/全局 → 什么都不用填；系统代理 → 自动识别；只有"都没有"才手填。

- 测试：`tests/test_proxy_check.py` 39 项（结论方向、SOCKS/PySocks、
  设置面板联动、异常兜底），全量 **427 项全绿**。
- 坑：`_explain()` 翻译异常时别把 requests 原文（两三百字符带内存地址）直接
  摆上界面——按 `_HINTS` 关键词表翻成人话 + 保留异常类名，认不出再截断到 120 字符。
