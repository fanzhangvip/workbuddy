## 交付

### 1. 集中主题层 `src/ui/theme.py`（新）
- `_PALETTE`：全部颜色的唯一来源（深空黑 `#05060A` 基底、玻璃白 7%/11%/17% 三档、
  钻石青 `#4FE3E8` 强调色、完整文字灰阶与语义色）。
- `apply_theme(app)`：先 QPalette 再全局 QSS（顺序反了会出现"样式表已换、
  palette 引用还是旧值"的灰字——QSS 的 `palette(...)` 在第一遍解析时替换）。
- `ink()`：自绘控件取色；`#AARRGGBB` 形态 QColor 不认，手工拆 alpha。
- `main.py` 在 QApplication 后立即装主题；`MainWindow.__init__` 兜底再装一次
  （测试/截图工具直接 new MainWindow 也要有主题）。

### 2. 布局重排（挤占的根源与对策）
- **主窗口顶部**：地址栏 + 8 按钮单行 → 地址栏独占整行 + 按钮行分三组
  （播放…诊断 / 弹簧 / 列表、设置）。量化：760px 窗口地址栏 168px→740px（4.4×）。
- **窄窗降级**：`resizeEvent` → `_apply_compact_layout`，1080/880 两档依次收
  「诊断/下载/加入列表」，最窄留 播放/粘贴/打开文件；「播放」任何宽度不收。
- **控制条**：单行 11 控件 → 两行（上行=进度+时间+音量，进度独占剩余宽度；
  下行=播放控制 | 弹簧 | 倍速/截图/外部/全屏）。760/640 两档从右往左收，
  全屏永不收。时间标签定宽 112px（防时间跳动横向抖动）。
- **播放列表面板**：5 按钮一行 → 左(加入/移除/清空) + 弹簧 + 右(上移/下移)。
- **设置面板**：5 个标签页各套 `QScrollArea`（`setWidgetResizable(True)` +
  隐藏横向滚动条），矮窗口滚动而不是挤压；按钮区加分隔线。
- **下载面板**：6 按钮一行 → 查看组 | 弹簧 | 操作组；620px 以下收查看组。
- **全屏**：顶部工具区（地址栏+按钮）收起，挂在 `changeEvent(WindowStateChange)`
  ——直接 showFullScreen() 也覆盖；`_top_area_visible` 闸门防 resizeEvent 撤销。

### 3. 顺手修掉的既有 bug（截图暴露的）
- `PlaylistPanel._refresh_empty_hint` 旧实现会把**没被选中的标签页里的视图**
  强制 `setVisible(True)`——Qt 不给未选中页做布局，尺寸冻结 640x480 越界渲染
  （截图里"列表行盖住底部按钮"）。改为只动当前页 + `tabs.currentChanged` 重算
  + 空提示文字说明是哪个列表。
- 播放中行高亮：未选中时用强调色+加粗，与"选中"区分。
- delegate 里说明文字在选中行改用 HighlightedText（淡灰压在青色选中底上看不清）。

### 4. 验证工具 `tools/ui_audit.py`（新）
多尺寸量控件几何，检出 过窄/过矮/塌陷/溢出/重叠 五类。判定要点（都踩过）：
- 下限别用 `minimumSizeHint()`：QHeaderView 假报 62x62；QLineEdit 只报 37px 宽。
- 输入类控件用 `_USABLE_WIDTH` 可用下限（QLineEdit=180 等）。
- `wordWrap=True` 的 QLabel 的 sizeHint 是"不折行"高度，只要求放下一行。
- 隐藏控件/未选中标签页里的视图保留冻结尺寸（640x480），必须跳过——
  判"父链 isHidden" + "栈容器当前页" 两道。
- 视口坐标：`viewport().rect()` 原点是视口自己，mapTo(parent) 才是父坐标；
  且要先确认视口尺寸 ≤ 控件外框（防止拿冻结视口判溢出）。
- 用改造前布局验证过检出能力：760px 下报 `[过窄] QLineEdit 168 < 180`。

- **冒烟失败先分辨"我改坏"还是"网络偶发"**：B 站 CDN 的音频分片偶发拒绝，
  单场景复跑 + stash 对照，别上来就回滚。

  （`_top_area_before_fullscreen` 在、`changeEvent` 不在）——重打包解决。
  以后打包期间一律冻结源码。
- PySide6 事件时序：构造期 `resize()` 的事件延迟到 show 才投递（所以
  resizeEvent 里访问 `_build_ui` 后才存在的属性是安全的，但别依赖这个顺序）。

- `dist/` 累积了 **25 个 stale 残留**（每个 onedir 384 MB / onefile 156 MB），
  合计 **6.5 GB**——`build.py` 的 `rmtree` 在本沙箱 fail-closed，删不掉只留名字。
- **清理办法（重要，以前以为删不掉）**：用 `PowerShell` 的
  `Remove-Item -LiteralPath <path> -Recurse -Force -Confirm:$false` **可以删除**，
  只是退出码会返回 1（`-Force` 冗长噪音），必须用 `Test-Path` 复核而不是看退出码。
  分批（≤10 个）逐项验证，两个过滤维度都要用：
  `-Directory -Filter "*.stale-*"` 与 `-File -Filter "*.stale-*"`
  （onedir 残留是目录、onefile 残留是单文件，只用一个过滤会漏）。
  `Add-Type`（Microsoft.VisualBasic 送回收站）和 `New-Object -ComObject
  Shell.Application`（COM）都被这个环境的策略拦截，直接用 `Remove-Item` 即可。
- 结果：`dist/` 从 6.5 GB → 540 MB，只剩 `UniversalURLPlayer/` 与
  `UniversalURLPlayer-single.exe` 两份目标产物。
- 冒烟复跑 12 项里 B 站合流那条又偶发失败一次，单场景复跑 2 次均通过
