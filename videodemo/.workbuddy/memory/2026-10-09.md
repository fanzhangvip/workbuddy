# 2026-10-09 —— 腾讯视频解析失败修复 + 解析超时可配置

## 用户需求

> "https://v.qq.com/x/cover/mzc00200jtsx0ds/v4102mfst3m.html?callTime=... 给我看下
> 腾讯的这个视频没法播放 解析超时 给我解决这个问题，如果是网络问题 这个超时时间
> 是否可以设置成 60 秒 不要弄太短了"

## 排查结论：不是网络问题

- `tools/site_check.py` 显示：v.qq.com **网络可达**（TCP 通），但解析 30 秒超时。
- yt-dlp 日志：`[vqq:video] unable to extract pinia data`。
- 抓页面验证：**页面里 `__pinia` 出现 0 次**——腾讯改版后数据改成脚本异步拉取
  （页面只剩 `window.__VINFO_DATA__` / `__VINFO_REQUEST_META__` 这些壳），
  yt-dlp 的 vqq 提取器必然报错，然后一路重试到硬超时（用户看到「解析超时」）。
- yt-dlp 已是最新（2026.8.19），**升级解决不了**，只能自己写提取。

## 解决方案：腾讯视频专用提取器（第 1.6 层，与好看视频同层）

接口实测（沙箱里全部可用）：

| 接口 | 结果 |
|---|---|
| `vv.video.qq.com/getinfo?vids=<vid>&platform=101001&charge=0&otype=json&defn=fhd` | ✅ `em=0`，给 `fn`(文件名) / `fvkey`(播放密钥) / `ul.ui[0].url`(CDN 节点) / `ti`(**本集标题**，如"交锋_02") / `vw`,`vh` / `fs` |
| `vv.video.qq.com/getvinfo?...` | ❌ `em=85 "这个视频被外星人劫走"`（已失效，别用） |
| 页面内嵌数据 | ❌ 无 `__pinia`、无 og:title，`<title>` 只有"腾讯视频"（SPA） |

拼地址：`{ul.ui[0].url}{fn}?vkey={fvkey}`（+ `Referer: https://v.qq.com/`）。
实测 hd=864x368 / shd=fhd=1280x546（免登录最高档），拉流 200 + `video/mp4`。

**效果**：`site_check` 端到端 **0.3 秒**解析成功，标题「交锋_02」、546P 单文件流。
（对比原来：30 秒超时失败。）

代码：`resolver.py` 的 `_TENCENT_*` 常量 + `_is_tencent` / `_tencent_vid` /
`_parse_qz_json` / `_extract_tencent`；`resolve()` 里 `if _is_tencent(target)` 接入。
`extractor_key` 用 `"qq"`，直接复用 `_EXTRACTOR_NAMES` 里的中文名「腾讯视频」。

## 解析超时改成可配置（默认 60 秒）

- 新增设置 `network/resolve_timeout_s`（默认 **60**，界面范围 10–300 秒）。
- `player_controller._resolve_worker` 调 `resolve()` 时传该值（**原来固定 25 秒**，
  慢站点会被误报"解析超时"）。
- `resolver.DEFAULT_TIMEOUT_S` 25 → **60**（没传参时的兜底），同步 3 处过时注释
  （resolver / settings / reachability）与 README ×2、教程 ×1。
- `tools/site_check.py` 的 `--timeout` 默认改为 None → 读设置，与主程序一致。
- 设置界面：「网络」页在「网络超时」下方新增「解析超时」。

  剥壳 / 拼地址 / 降档回退 / 拿不到返回 None / 超时默认值），全过。

- 设置面板离屏验证：默认 60、范围 10–300、`_collect()` 写入 `network/resolve_timeout_s` ✅

## 下午追加：爱奇艺解析修复 + 优酷会员内容的明确提示

## 用户需求

> "https://www.iqiyi.com/v_1gu30dui6vo.html?qyTrace=... 爱奇艺的也没法播放 给我解决好"
> "https://v.youku.com/v_show/id_XNjU2NjE5MzI2OA==.html?... 优酷的也没法播放 也要给我解决"

## 排查结论

- **爱奇艺**：yt-dlp 报 `[iqiyi] Can't find any video`。根因是它的提取器要在页面里
  找 `data-player-tvid` / `data-player-videoid` 属性拿 tvid，**爱奇艺改版后播放页
  成了纯前端渲染，这两个属性已经不存在** → 判定"没有视频"。升级 yt-dlp 无用。
- **优酷**：yt-dlp 报 `Youku server reported error -3007: 观看此节目，请先登录！`。
  这条**不是提取器坏了**——用同剧的免费片段测试，yt-dlp **能正常解析出 2~3 个
  格式**（m3u8）。所以优酷本身是被支持的，这条视频是**会员（VIP）内容**。
  佐证：页面 `__INITIAL_DATA__` 里 `paid=1`；ups 接口 `fee.paid=1,
  paid_type=["mon"]`、`pay.can_play=false`。
- **顺带确认：用户给的这条爱奇艺视频在页面上标 `isVip=True`，但实测免登录
  仍能取到完整正片**（低清晰度档）。所以"标了 VIP" ≠ "取不到流"，必须实测。

## 解决方案

### 1. 爱奇艺专用提取器（第 1.7 层，与好看/腾讯同层）

接口链（**别用桌面 UA，会被判 `Rule Block`**）：

| 步骤 | 接口 | 拿到什么 |
|---|---|---|
| 1 | `https://m.iqiyi.com/v_<id>.html`（移动端页面，SSR 带数据） | `window.__INITIAL_STATE__` → `play.videoInfo.tvid` / `play.loadInfo.vid` / 标题 / 时长 |
| 2 | `http://cache.m.iqiyi.com/jp/tmts/<tvid>/<vid>/` + 签名 | `data.m3u`（m3u8 地址）、`data.vidl`（清晰度列表）、`data.screenSize`、`data.code` |

签名（与 yt-dlp 同一套）：`sc = md5(毫秒时间戳 + 'd5fb4bd9d50c4be6948c97edd7254b0e' + tvid)`，
参数 `tvid` / `vid` / `src=76f90cbd92f94a2e925d83e8ccd22cb7` / `sc` / `t`。
URL 路径里的 `vid` 换成某个清晰度的 vid，就返回**那一档**的流。

清晰度（实测同一视频）：

| 请求的 vid 的 vd | 拿到的 screenSize | code | 说明 |
|---|---|---|---|
| 4 | **1280x720** | 2 | 免登录最好档（选它） |
| 17 | 1280x720 | 1 | 会员档 |
| 21 / 75 / 2 | 896x504 | 2 / 2 / 2 | |
| 1 | 640x360 | 2 | |
| 96（接口默认给的那条） | **384x216** | 2 | 兜底用 |

`code=2` = 当前身份可取；`code=1` = 多为需会员。**取流时长 1069 秒 ≈ 正片 17:50
（262 个分片），确认是完整正片、不是试看**（`qd_vip=0`、`previewType` 为空）。

代码：`_IQIYI_*` 常量 + `_is_iqiyi` / `_iqiyi_vid` / `_json_after` /
`_iqiyi_page_info` / `_iqiyi_tmts` / `_iqiyi_quality_candidates` /
`_split_resolution` / `_extract_iqiyi`；`resolve()` 里 `if _is_iqiyi(target)` 接入。
选档策略：先用接口默认的 `m3u` 兜底，再按 `_IQIYI_VD_ORDER` 试最多 3 档，
第一个 `code=2` 的胜出（多试几个会把"快"耗掉）。

**效果**：`site_check` 端到端 **0.9 秒**解析成功——「余红旧事第1集」720P
（是用户地址指向的第 1 集，标题来自页面 SSR）。

### 2. 会员内容给明确的中文提示

`_ERROR_RULES` 原来只认英文关键词（`login` / `vip` / `premium`…），而国内站点
报的是中文（优酷 `-3007 观看此节目，请先登录！` 里既没有 `login` 也没有 `vip`）
→ 整个漏过去，用户最后只看到一句没用的"解析失败"。补一条**中文规则**（放在英文
登录规则之前）：`请先登录` / `需要登录` / `开通会员` / `-3007` / `-3008` →
"该视频是会员（VIP）内容…不是地址或网络问题，换清晰度、调超时都没用…
先在浏览器登录会员账号，再开启「从浏览器读 Cookie」"。

**效果**：优酷那条从"22.8 秒的无用失败"变成 **1.5 秒**的明确说明。

  "规则表只认英文会漏中文"这条教训。

## 坑与结论（写进 MEMORY）

- **"页面标了 VIP" 不等于 "取不到流"**：爱奇艺这条 `isVip=True` 但免登录能拿到
  完整正片（低清晰度）。必须**实测**再下结论。
- **同一站点要分开判"提取器坏"和"内容受限"**：优酷是内容受限（免费片段能解），
  爱奇艺是提取器坏（换免费视频也解不了）。判据 = 拿同站的免费内容跑一次。
- **沙箱拦 `data.video.iqiyi.com`**（本地代理返 `404 Route Not Found`，
  36 字节 `{"error_msg":"404 Route Not Found"}`）→ 爱奇艺的**分片**在沙箱里
  拉不到，**播放列表（`mus.video.iqiyi.com`）可以**。所以只能验证到"解析出正确
  的 m3u8"，端到端播放要在真实环境验。
- **爱奇艺不需要请求头**：实测同一条带 token 的 m3u8，用「移动 UA + Referer」/
  「桌面 Chrome UA」/「无自定义头」/「空头」四种方式请求**全都是 200、266 个分片**
  ——鉴权全在 URL 的 `qd_k`/`qd_sc`/`vf` token 里。所以即便 Qt 后端注入不了
  Referer（`local_proxy` 对 HLS 清单不代理 → 必然出现那句
  "Qt 后端无法注入 HTTP 请求头…可能因防盗链失败"的警告），iQiyi 也能播。
  `http_headers` 仍旧照常返回——**mpv 内核能注入**（`http-header-fields`），
  换内核时就用得上。
- **`dist/` 里有一个 stale 删不掉**：`UniversalURLPlayer-single.exe.stale-20261009-174214`
  （163 MB）**正被两个还在运行的旧实例占用**（PID 32100 / 36232，17:06 启动、
  路径 `dist/UniversalURLPlayer-single.exe`，应是你自己打开的产物）。
  `Remove-Item` 走的是沙箱 `safe-delete` 钩子 → `SAFE_DELETE_FAIL_CLOSED /
  trash-failed`；想改成"先清空再删"也被拒（文件被占用）。
  **没擅自结束进程**。关掉那两份实例后即可删除。
  另：这次产物级实跑日志里能看到 17:08 / 17:12 你本人的两次尝试
  （爱奇艺 `Can't find any video`、优酷 `Unable to download webpage: SSL
  UNEXPECTED_EOF`）——印证了问题现象。
