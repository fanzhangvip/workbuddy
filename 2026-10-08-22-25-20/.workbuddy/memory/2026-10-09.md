## RRF（倒数排名融合）技术解答与实现

- 讲解了 AI Agent / RAG 中 RRF 的原理：多路召回（向量 + BM25 等）分数不可比，
  改用排名倒数累加 `score(d) = Σ 1/(k + rank_i(d))`，k 惯例取 60。
  链路位置：多路召回 → RRF 融合 → Cross-encoder 精排 → Top-K → LLM。
  澄清了 RRF（排名融合，廉价）与 Rerank（Cross-encoder 精排，昂贵）的区别。
- 新增文件 `rrf.py`（项目根目录）：零依赖的 RRF 最小实现，含 `rrf_fuse()`、
  `to_ranked()` 辅助函数和一个可运行的 demo。已用 Python 3.13 验证，
  示例输出 d3=0.03252 / d1=0.03227 / d7=0.01613 / d9=0.01587。

## 多租户隔离方案讨论（架构线索）

- 用户项目的现状：`user_id` 作为每张业务表的「第二主键」，多租户隔离由
  应用层 DAO 的 `WHERE user_id = ?` 实现，**未启用数据库 RLS**；
  其自述风险是「安全性依赖每个 DAO 方法都记得带 user_id 这一纪律」。
- 已解释 PostgreSQL RLS（Row-Level Security）：CREATE POLICY + ENABLE ROW
  LEVEL SECURITY + 会话变量 `current_setting()`，把隔离从「应用纪律」
  下沉为「数据库强制」。已提醒注意连接池下会话变量必须用 SET LOCAL 绑定事务、
  表 owner / BYPASSRLS 角色会绕过策略、需注意性能与迁移成本。
